# CURRICULUM V2: Middle Golang Developer Path

Этот учебный план — твой путь от самых основ языка до уровня уверенного Middle-разработчика.

**Ключевой принцип:** Мы не зазубриваем синтаксис. Каждая тема изучается через фундаментальное осознание того, как Go работает "под капотом", какие есть узкие места, частые ошибки (gotchas) и как их избегать на практике. Однажды поняв фундамент — ты запомнишь это навсегда.

Инструкция для Агента: При переходе к каждой новой теме генерировать `PLAN.md`, содержащий множественные циклы практик (`practice_01`, `practice_02`...), которые будут планомерно усложнять задачу, бить по краевым случаям и требовать написания реального кода.

## Этап 1: Фундамент и Механика Памяти
- [ ] `01_variables_and_types` (Абсолютные азы: `var`, `:=`, размеры типов в памяти, как компилятор выбирает типы, частые ошибки при конвертации)
- [ ] `02_control_flow` (Глубокое понимание `for`, `switch`, `if`, краевые случаи с `range`, ловушки с копированием переменных в цикле)
- [ ] `03_pointers_and_memory` (Как работает память: Куча vs Стек, Escape Analysis, передача по значению vs по ссылке, безопасность указателей)

## Этап 2: Структуры Данных под Микроскопом
- [ ] `04_arrays_and_slices` (Внутреннее устройство: Slice Header, формула роста capacity, скрытые утечки памяти, правильное копирование)
- [ ] `05_hash_maps` (Устройство `hmap`, бакеты, коллизии, эвакуация при росте, фатальные ошибки при конкурентном доступе)
- [ ] `06_strings_and_runes` (String Header, иммутабельность, разница между байтами и рунами, оптимизация аллокаций при конкатенации)
- [ ] `07_structs_and_alignment` (Компоновка структур, выравнивание памяти (Alignment/Padding), оптимизация размера структуры)

## Этап 3: Архитектура Кода (ООП без классов)
- [ ] `08_methods_and_receivers` (Pointer vs Value receivers, частые ошибки при изменении состояния)
- [ ] `09_interfaces` (Пустой интерфейс `any`, внутреннее устройство `itab`, утиная типизация, композиция вместо наследования)
- [ ] `10_error_handling` (Идиоматичная обработка ошибок, `errors.Is`, `errors.As`, оборачивание ошибок, паники и `defer`)

## Этап 4: Конкурентность (Concurrency)
- [ ] `11_goroutines_and_scheduler` (Основы GMP-планировщика, как горутины работают под капотом, утечки горутин)
- [ ] `12_channels` (Буферизованные и небуферизованные каналы, `select`, дедлоки, паттерны Worker Pool и Pipeline)
- [ ] `13_context` (Управление жизненным циклом горутин, таймауты, отмена операций, передача значений)

## Этап 5: Синхронизация и Производительность
- [ ] `14_sync_primitives` (`Mutex`, `RWMutex`, `WaitGroup`, `Map`, состояние гонки (Race Condition))
- [ ] `15_atomic_operations` (Пакет `sync/atomic`, lock-free программирование)
- [ ] `16_profiling_and_benchmarks` (Написание бенчмарков, профилирование через `pprof`, поиск узких мест CPU и RAM)

## Этап 6: Боевые Проекты (Портфолио)
Эти проекты покажут работодателю, что ты умеешь решать реальные бизнес-задачи, писать чистый и производительный код, а также понимаешь архитектуру современных распределенных систем.
- [ ] `project_01_concurrent_log_analyzer` (Утилита командной строки, которая асинхронно парсит гигабайты логов, использует Worker Pool и каналы для агрегации данных без перегрузки RAM).
- [ ] `project_02_distributed_rate_limiter` (Сервис ограничения запросов (Rate Limiter) с использованием алгоритма Token Bucket, работающий по TCP/HTTP с защитой от состояния гонки).
- [ ] `project_03_mini_redis` (Собственный In-Memory Cache сервер со сроком жизни ключей (TTL), кастомным бинарным протоколом и персистентностью на диск).
- [ ] `project_04_custom_load_balancer` (Reverse Proxy / Балансировщик нагрузки, распределяющий HTTP-запросы между серверами по алгоритму Round-Robin. Глубокая работа с `net/http`, `httputil.ReverseProxy`, контекстом и проверкой состояния серверов (Healthchecks)).
- [ ] `project_05_grpc_auth_microservice` (gRPC Сервис авторизации. Выдача и валидация JWT-токенов через бинарный протокол gRPC. Работа с Protobuf и понимание межсервисного взаимодействия в энтерпрайз-среде).
