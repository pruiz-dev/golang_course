# Теория: Метки (Labels) и выход из вложенных циклов

Иногда алгоритм требует использования вложенных циклов (цикл внутри цикла). Классический пример: поиск конкретного элемента в двумерном массиве (матрице) или перекрестная проверка данных.

## Проблема `break` во вложенных циклах
Ключевое слово `break` прерывает только **тот цикл, внутри которого оно вызвано**.

```go
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if j == 1 {
            break // Этот break выйдет только из внутреннего цикла (j). Внешний (i) продолжит работу!
        }
    }
}
```
В старых языках разработчикам часто приходилось заводить переменные-флаги (например, `found := true`), чтобы проверять их во внешнем цикле и делать двойной `break`. Это плодит грязный "спагетти-код".

## Решение: Использование меток (Labels)
Go предлагает элегантное и мощное решение — **метки (Labels)**. 
Ты можешь дать имя любому циклу, написав слово и двоеточие прямо перед ним. А затем передать это имя команде `break` или `continue`.

```go
OuterLoop: // Это метка для внешнего цикла
for i := 0; i < 5; i++ {
    for j := 0; j < 5; j++ {
        if i == 2 && j == 2 {
            fmt.Println("Нашли нужный элемент, выходим вообще из всех циклов!")
            break OuterLoop // Прерывает цикл, помеченный как OuterLoop
        }
    }
}
```

### `continue` с метками
Метки работают и с `continue`. Если во внутреннем цикле ты сделаешь `continue OuterLoop`, программа немедленно прервет текущую итерацию внутреннего цикла и прыгнет на **следующую итерацию внешнего цикла**.

> **Важно:** Метки в Go не имеют ничего общего с опасным оператором `goto`. `break Label` можно использовать только для выхода из блоков. Он не позволяет прыгать в произвольное место кода (что могло бы сломать логику и память), поэтому это абсолютно безопасный, идиоматичный подход.
