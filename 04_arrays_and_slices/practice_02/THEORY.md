# Теория: Рост слайса (append) и разница между Len и Cap

Мы уже выяснили, что слайс — это структура из трех полей: указатель на массив `Data`, длина `Len` и вместимость `Cap`.
Пришло время разобраться, зачем нужны эти `Len` и `Cap`, и почему их две.

## 1. Разница между Длиной (Len) и Вместимостью (Cap)
* **Длина (`len`)** — это количество элементов, которые *уже записаны* в слайс и доступны тебе прямо сейчас.
* **Вместимость (`cap`)** — это физический размер скрытого базового массива в памяти. Это потолок, до которого слайс может расти без выделения новой памяти.

Представь, что слайс — это автобус:
- `Cap` — это количество сидений в автобусе (например, 10).
- `Len` — это количество пассажиров, которые сейчас сидят внутри (например, 3).

## 2. Функция `append`
В Go слайсы динамические. Чтобы добавить новый элемент, мы используем встроенную функцию `append`.

```go
// Создаем пустой слайс (нулевое значение)
var inventory []string // len=0, cap=0, Data=nil

// Добавляем элемент
inventory = append(inventory, "Зелье")
```

### Главный закон `append`: ВСЕГДА переприсваивай результат!
Ты никогда не должен писать просто `append(inventory, "Зелье")`. Ты обязан написать `inventory = append(...)`. 
**Почему?**
Потому что функция `append` **возвращает новую структуру `SliceHeader`** (те самые 24 байта). Если массив пришлось расширить, указатель `Data` в новом заголовке изменится! Если ты не перезапишешь старую переменную новой структурой, ты просто потеряешь добавленные данные.

## 3. Как слайс растет (Аллокация памяти)
Что происходит под капотом при вызове `append`, если `len == cap` (автобус забит битком, все места заняты)?
1. Go видит, что свободного места в скрытом массиве нет.
2. Go идет в Кучу (Heap) и **создает новый скрытый массив** бОльшего размера. Обычно он увеличивает `cap` в 2 раза (x2), чтобы не делать это слишком часто.
3. Go **копирует** все старые элементы из старого массива в новый.
4. Go добавляет твой новый элемент.
5. Go возвращает тебе новую структуру 24 байта, где указатель `Data` смотрит уже на новый большой массив, а `Cap` увеличен вдвое.
6. Старый скрытый массив остается в Куче в виде мусора, который потом уберет Garbage Collector.

### Что физически происходит при переприсваивании `s = append(...)`?
Отличный и очень глубокий вопрос: *"Если `append` возвращает новую структуру, значит ли это, что переменная `s` теперь указывает на новый адрес памяти (где-то лежит новая структура)?"*

**Нет, адрес самой переменной `s` не меняется!**
Вспомни, как работают обычные числа:
```go
x := 10 // Переменная x лежит на Стеке по адресу 0xAAA (занимает 8 байт).
x = 20  // Адрес 0xAAA не изменился! Мы просто перезаписали старые 8 байт новыми.
```
Точно так же работает и слайс:
```go
// Переменная inventory лежит на Стеке по адресу 0xBBB (занимает 24 байта).
var inventory []string 

// append возвращает "в воздухе" новые 24 байта. 
// Знак равенства (=) просто берет эти новые 24 байта и ЖЕСТКО ПЕРЕЗАПИСЫВАЕТ 
// старые 24 байта, лежащие по тому же самому адресу 0xBBB.
inventory = append(inventory, "Зелье") 
```
То есть, для компилятора переменная `inventory` осталась ровно на том же месте. Изменилась только **начинка** этой переменной (внутри перезаписался указатель `Data` и обновились числа `Len` и `Cap`).

## 4. Функция `make` (Предварительная аллокация)
Если ты заранее знаешь, что убьешь 10 монстров и соберешь 10 предметов, надеяться на автоматический рост `cap` через `append` — это плохая идея. Go будет постоянно выделять новую память и копировать старые данные туда-сюда. Это медленно.

Чтобы сразу "заказать автобус на 10 мест", используется встроенная функция `make`:
```go
// len=0 (пока пусто), cap=10 (память уже выделена)
inventory := make([]string, 0, 10) 
```
Теперь ты можешь сделать 10 раз `append`, и Go не будет ни разу перевыделять память и ничего копировать под капотом!
