# Теория: Массивы vs Слайсы

В Go есть два разных типа для хранения списков элементов: **Массивы (Arrays)** и **Слайсы (Slices)**. Новички часто их путают, потому что они выглядят похоже, но под капотом ведут себя кардинально по-разному.

## 1. Массив (Array)
Массив имеет **фиксированную длину**, которая задается при создании. Длина массива является частью его типа! 
Это значит, что `[3]int` и `[5]int` — это два абсолютно разных типа данных, как `int` и `string`.

```go
// Объявление массива
var a [3]string
b := [3]string{"Меч", "Щит", "Зелье"}
```

**Что физически лежит внутри переменной-массива?**
Если ты объявляешь массив, то **прямо внутри этой переменной** (в её ячейке памяти) физически лежат сами значения. Если у тебя `[3]int` на 64-битной системе, то переменная занимает ровно 24 байта (3 * 8). В ней нет никаких метаданных, указателей или структур. Только сырые данные.

- **Не инициализирован (Zero Value):** 
  ```go
  var a [3]int
  ```
  Go выделяет 24 байта под эту переменную и просто забивает их нулями на уровне процессора. Внутри переменной `a` физически лежит `[0, 0, 0]`. Она уже существует и готова к работе. Запись `a[0] = 10` просто перезапишет первые 8 байт.
- **Инициализирован:** 
  ```go
  a := [3]int{10, 20, 30}
  ```
  Внутри переменной `a` лежат именно эти три числа.

**Критическая особенность массивов:**
Поскольку внутри переменной лежат сами данные, при передаче массива в функцию (`func Do(arr [1000]int)`) язык копирует **всю переменную**. То есть физически дублирует все 1000 элементов в новую область памяти.

## 2. Слайс (Slice)
Слайс переводится как "срез". Это **динамический** список. У него не указан размер в квадратных скобках.

```go
// Объявление слайса (обрати внимание, в скобках пусто)
var s []string
items := []string{"Монета", "Ключ"}
```

**Что физически лежит внутри переменной-слайса?**
Переменная-слайс — это НЕ сами данные. Переменная-слайс — это **всегда** крошечная структура (`SliceHeader`), которая весит ровно 24 байта. Внутри ячейки памяти этой переменной всегда лежат строго три поля:
1. `Data` (8 байт) — указатель на реальный скрытый массив, где лежат данные.
2. `Len` (8 байт) — длина (сколько элементов доступно).
3. `Cap` (8 байт) — вместимость (сколько памяти выделено "про запас").

- **Не инициализирован (Zero Value):**
  ```go
  var s []int
  ```
  Go выделяет 24 байта под переменную `s` и заполняет её нулями. Получается такая структура:
  - `Data = nil` (адрес `0x00000000`)
  - `Len = 0`
  - `Cap = 0`
  *Важное уточнение про `nil`:* Сама "пустая" структура в Go **не равна `nil`**. Переменная `s` существует аппаратно. Но создатели Go добавили синтаксический сахар: если поле `Data` равно `nil`, то проверка `s == nil` возвращает `true`. 
  Так как указатель пуст, попытка сделать `s[0] = 10` приведет к немедленной панике (попытка сходить по адресу `0x0`). Наполнять такой слайс можно только через функцию `append()`.

- **Инициализирован:**
  ```go
  s := []int{10, 20}
  ```
  Go где-то глубоко в Куче создает скрытый безымянный массив `[10, 20]`. А внутрь твоей переменной `s` записывает:
  - `Data = 0xc000...` (адрес того самого скрытого массива)
  - `Len = 2`
  - `Cap = 2`

**Критическая особенность слайсов:**
Когда ты передаешь слайс в функцию, копируется **только переменная `s`**, то есть эта 24-байтовая структура. Указатель `Data` внутри копии продолжает смотреть на тот же самый скрытый массив в Куче. Поэтому изменение данных через копию отразится на оригинале!
