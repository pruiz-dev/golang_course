# Теория: Правильное копирование и функция `copy()`

В прошлой практике мы узнали, что нарезка (slicing) не копирует данные физически, а лишь создает новое окно на старый массив. Если старый массив огромный, а окно маленькое — это приведет к серьезной утечке памяти, так как сборщик мусора не сможет удалить гигантский массив.

Как же "спасти" нужные данные и отвязаться от огромного куска памяти?
Ответ: нужно **физически скопировать** нужные байты в совершенно новый массив, а про старый слайс забыть.

## Функция `copy()`
Для этого в Go есть встроенная функция `copy(dst, src)` (копировать из источника `src` в место назначения `dst`).

```go
// 1. Представь, что у нас есть огромный файл (1 МБ)
hugeFile := make([]byte, 1000000)

// 2. Мы создаем СОВЕРШЕННО НОВЫЙ слайс нужного размера (5 байт)
// len = 5, cap = 5
safeHeader := make([]byte, 5)

// 3. Физически копируем данные из огромного файла в наш новый маленький слайс
// copy скопирует ровно столько элементов, сколько влезет в safeHeader
copy(safeHeader, hugeFile)
```

**Что произошло под капотом?**
1. `make([]byte, 5)` аллоцировал в Куче совершенно новый независимый массив на 5 ячеек памяти.
2. `copy` аппаратно перенес 5 байт из гигантского массива в этот новый 5-байтовый массив.
3. Теперь `safeHeader` смотрит на свой собственный маленький массив (`cap = 5`).
4. Как только функция завершится, огромный массив `hugeFile` останется без ссылок, и Garbage Collector радостно удалит 1 Мегабайт памяти!

## Важное правило `copy`
Функция `copy` копирует ровно `min(len(dst), len(src))` элементов. 
Это значит, что если ты создашь пустой слайс `dst := make([]byte, 0)` и попытаешься скопировать в него данные, то скопируется ровно 0 элементов! Целевой слайс `dst` **должен иметь выделенную длину (`len`)**, достаточную для вмещения данных.
