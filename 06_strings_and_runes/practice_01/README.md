# Практика 01: Инспектор Текста (Text Inspector) — Анатомия строк в Go

## Контекст задачи
В реальных проектах на Go микросервисы постоянно работают с многоязычным текстом: именами пользователей, заголовками статей, эмодзи в чатах, метаданными файлов.  
Если разработчик не понимает разницу между байтом и руной, возникают классические баги:
* Обрезание строки пополам посередине русской буквы или эмодзи, что ломает JSON и выдает невалидный UTF-8.
* Неправильный расчет лимитов длины сообщений в валидаторах.
* Неверный поиск подстрок и расчет смещений.

Ваша задача — с нуля разработать консольную утилиту **Text Inspector**, которая наглядно демонстрирует физическое устройство строк в Go.

---

## Техническое задание (Requirements)

Входные данные для анализа — тестовая строка, содержащая символы разной байтовой длины (1, 2 и 4 байта):
```go
"Go: Привет 🚀"
```
*(Вы можете сделать ввод через переменную или константу, либо чтение аргументов).*

Программа должна выполнить 4 блока анализа:

### 1. Общая метрика размера
* Вычислить и вывести физический размер строки в памяти (в байтах).
* Вычислить и вывести количество реальных символов (кодовых точек Unicode).
* Показать наглядно разницу между этими двумя величинами.

### 2. Демонстрация ловушки побайтовой индексации
* Показать, что возвращает выражение прямого доступа по индексу (например, `s[0]` и `s[4]`).
* Вывести тип полученного значения (убедиться, что это `uint8 / byte`).
* Показать, к чему приводит наивная попытка распечатать `string(s[4])` для первого байта русской буквы (демонстрация искажения символа).

### 3. Порунный рентген (Unicode Decode Table)
* Обойти строку и для каждого неделимого символа вывести структурированную строку/таблицу:
  * **Байтовое смещение** (offset), с которого начинается руна.
  * **Сам символ** (человекочитаемый вид).
  * **Размер в байтах**, который этот символ физически занимает в UTF-8 (1, 2, 3 или 4 байта).
  * **Unicode-код** (в стандартном формате `U+XXXX`).

### 4. Безопасное извлечение по порядковому номеру
* Написать функцию или блок кода, который безопасно извлекает $N$-й по счету символ строки (например, 5-й символ слова "Привет" или эмодзи) и возвращает его в виде корректной строки, не повреждая кодировку UTF-8.

---

## Критерии приемки (Acceptance Criteria)
1. Код компилируется и запускается без ошибок через `go run main.go`.
2. Физический размер строки корректно посчитан через встроенную функцию `len()`.
3. Количество рун корректно посчитано через стандартный пакет `"unicode/utf8"`.
4. Для определения размера отдельной руны в байтах используется идиоматичный подход (например, функция `utf8.RuneLen()` или разница между соседними смещениями).
5. При обходе строки ни один многобайтовый символ (кириллица, эмодзи) не искажается и выводится корректно.
6. Вывод программы аккуратно отформатирован с помощью глаголов форматирования пакета `fmt` (`%c`, `%d`, `%U`, `%T`, `%q`).

---

## Архитектурные подсказки (High-Level Hints)
* Вам понадобится пакет `main` и функция `main()`.
* Для работы с UTF-8 стандартная библиотека Go предоставляет богатый пакет `"unicode/utf8"`. Изучите функции `utf8.RuneCountInString` и `utf8.RuneLen`.
* Для форматирования:
  * `%c` выводит руну как символ Unicode.
  * `%U` выводит кодовую точку в виде `U+0047`.
  * `%T` выводит тип переменной.
* Помните, что `for idx, r := range str` автоматически декодирует UTF-8, но `idx` — это байтовое смещение, а не порядковый номер 1, 2, 3...
