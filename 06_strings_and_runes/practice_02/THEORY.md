# Теория: Иммутабельность и Редактирование строк в Go

## 1. Почему строки в Go иммутабельны (Read-Only)?

В Go строки фундаментально **неизменяемы**. Если строка создана, ни один её байт в памяти изменить нельзя.

```go
s := "hello"
s[0] = 'H' // ОШИБКА КОМПИЛЯЦИИ: cannot assign to s[0]
```

### Зачем создатели Go сделали строки иммутабельными?
1. **Безопасность многопоточности (Thread Safety):** Десятки горутин могут одновременно читать одну и ту же строку без мьютексов и блокировок. Состояние гонки (Data Race) невозможно в принципе, потому что данные никто не может изменить.
2. **Оптимизация памяти ОС (Read-Only сегмент):** Строковые литералы из исходного кода (`"hello"`) компилятор помещает в специальную секцию `.rodata` исполняемого файла. Эта память на уровне операционной системы помечена как «только для чтения». Попытка записать туда что-либо на аппаратном уровне вызвала бы аварийное падение программы (*Segmentation Fault*).
3. **Бесплатная передача и нарезка:** Взятие подстроки `sub := s[1:4]` или передача строки в функцию не копирует саму строку — копируется лишь маленький 16-байтовый заголовок `StringHeader`.

---

## 2. Как же тогда «изменить» строку?

Единственный способ изменить строку в Go — **создать в памяти совершенно новую строку** с нужными изменениями.

Для этого исходную строку сначала преобразуют в изменяемый срез (мутируют его), а затем преобразуют обратно в строку. Существует два принципиально разных подхода:

---

### Подход 1: Конвертация в срез байтов `[]byte(s)`
Идеален, когда строка состоит **исключительно из 1-байтовых символов ASCII** (английский текст, цифры, разделители, протоколы):

```go
s := "hello"
b := []byte(s) // 1. Выделяется срез байтов []uint8 (копия данных)
b[0] = 'H'     // 2. Меняем байт на месте
newS := string(b) // 3. Создается новая иммутабельная строка "Hello"
```

* **Плюсы:** Минимальный расход памяти (1 байт на символ), максимальная скорость.
* **Главная опасность (Катастрофа на UTF-8):** Если в строке есть кириллица или эмодзи, попытка работать через `[]byte` разорвет многобайтовый символ!

```go
ru := "Кот" // Байты: [0xD0 0x9A] [0xD0 0xBE] [0xD1 0x82] (всего 6 байт)
b := []byte(ru)
b[0] = '*' // Мы заменили только 1-й байт буквы 'К'!
fmt.Println(string(b)) // Выведет: *от (МУСОР и кракозябра!)
```

---

### Подход 2: Конвертация в срез рун `[]rune(s)`
Единственный корректный способ при работе с **многоязычным текстом (Unicode / UTF-8)**:

```go
ru := "Кот"
runes := []rune(ru) // 1. Распаковывает строку в срез []int32
runes[0] = 'К'
runes[1] = 'и'
newRu := string(runes) // 2. Упаковывает руны обратно в UTF-8 строку
fmt.Println(newRu)     // "Кит" (Идеально!)
```

#### Что происходит под капотом при `string(runes)`?
Go берет распакованные 4-байтовые руны и заново кодирует каждую в UTF-8.
* Если ты заменил руну `'К'` (2 байта) на ASCII-символ `'*'` (1 байт):
  ```go
  runes[0] = '*'
  res := string(runes) // res станет "*от"
  ```
* Go сам корректно пересчитает итоговый физический размер: было 6 байт (`Кот`), стало 5 байт (`*от`). Никаких повреждений кодировки не произойдет!

---

## 3. Скрытая цена: Сколько памяти стоит модификация строки?

Каждая конвертация строки в срез и обратно — это **аллокация в куче (Heap Allocation)** и копирование памяти:

| Операция | Что происходит в памяти | Расход памяти |
| :--- | :--- | :--- |
| `b := []byte(s)` | Выделяется новый срез байт, байты копируются | $N$ байт |
| `newS := string(b)`| Выделяется новая строка, байты копируются | $N$ байт |
| `r := []rune(s)` | Выделяется срез `int32`, каждая руна распаковывается | **$4 \times K$ байт** ($K$ — число рун) |
| `newS := string(r)`| Выделяется новая строка, руны сжимаются в UTF-8 | $N$ байт |

> 💡 **Правило Middle-разработчика:**  
> Если нужно модифицировать одиночные символы в сложном Unicode-тексте — используй `[]rune`.  
> Если нужно массово собирать или модифицировать большие объемы текста — используют `strings.Builder` или `bytes.Buffer` (их мы изучим в практике 03).
