# Теория: Конкатенация строк и strings.Builder

## 1. Проблема оператора `+` в цикле (сложность O(N²))

В Go строки **иммутабельны**. Память, выделенная под строку, зафиксирована навсегда.  
Когда мы пишем:

```go
s := "a"
s = s + "b"
```

Рантайм Go не может просто дописать байт `'b'` в конец существующей памяти. Он вынужден:
1. Выделить в куче (Heap) **новый кусок памяти** размером `len("a") + len("b") = 2 байта`.
2. Скопировать байты из `"a"`.
3. Скопировать байты из `"b"`.
4. Перенаправить указатель переменной `s` на новый кусок памяти.
5. Старый кусок памяти (`"a"`) оставить в куче мусором для Garbage Collector (GC).

### К чему это приводит в цикле?
Представь, что мы собираем строку из N = 50 000 коротких фрагментов (по 11 байт каждый):

```go
var s string
for i := 0; i < 50000; i++ {
    s += "log record\n"
}
```

* На 1-й итерации: строка длины 11 байт.
* На 2-й итерации: выделяется 22 байта, копируются старые 11 + новые 11.
* На 3-й итерации: выделяется 33 байта, копируются старые 22 + новые 11.
* ...
* На 50 000-й итерации: выделяется 550 000 байт, копируются старые 549 989 + новые 11!

Суммарно процессор скопирует:
11 * (1 + 2 + 3 + ... + 50 000) байт.
По формуле арифметической прогрессии: 11 * (50 000 * 50 001 / 2) ≈ 13.7 гигабайт памяти!

Вместо быстрого линейного времени O(N) программа получает квадратичную сложность O(N²) по времени и выделению памяти.  
Сборщик мусора (GC) перегружается миллионами временных строк, CPU тратит такты на постоянное копирование, а производительность падает в сотни раз.

## 2. Почему `bytes.Buffer` был не идеален?

До версии Go 1.10 разработчики собирали строки через `bytes.Buffer`:
```go
var buf bytes.Buffer
for i := 0; i < 50000; i++ {
    buf.WriteString("log record\n")
}
result := buf.String()
```
`bytes.Buffer` решает проблему квадратичного копирования во время цикла (срез растет геометрически с запасом `cap`).  
**Но в самом конце кроется скрытая аллокация:**
Метод `buf.String()` делает внутри:
```go
return string(buf.Bytes()) // Лишнее копирование всего буфера в новую строку!
```
Если буфер накопил 100 МБ данных, финальный вызов `.String()` выделит **еще 100 МБ** в куче и скопирует все данные заново, чтобы гарантировать иммутабельность строки.

## 3. Решение: `strings.Builder` (Zero-Copy)

В Go 1.10 появился специальный инструмент: **`strings.Builder`** (пакет `"strings"`).  
Он разработан специально для высокопроизводительной сборки строк.

```go
import "strings"

var sb strings.Builder
sb.WriteString("Привет")
sb.WriteByte(' ')
sb.WriteRune('🚀')
result := sb.String()
```

### Главная магия: Zero-Copy в `.String()`
Внутри `strings.Builder` хранит обычный срез байт `buf []byte`.  
Когда ты вызываешь `sb.String()`, он **НЕ копирует данные**! С помощью встроенного `unsafe.Pointer` он мгновенно превращает внутренний срез байтов в строку:

```go
// Упрощенный исходный код strings.Builder из стандартной библиотеки:
func (b *Builder) String() string {
    return *(*string)(unsafe.Pointer(&b.buf))
}
```
Финальное преобразование происходит **мгновенно за O(1) и с нулевыми аллокациями памяти**!

## 4. Суперсила преаллокации: Метод `.Grow(n)`

По умолчанию `strings.Builder` начинает с пустого буфера и увеличивает его по мере поступления данных (удваивая `cap`, как обычный срез). Каждое удвоение — это аллокация новой памяти и копирование старого буфера.

Если ты хотя бы приблизительно знаешь будущий размер итоговой строки (например, 50 000 записей по ≈ 20 байт = 1 МБ), вызови метод **`Grow()`**:

```go
var sb strings.Builder
sb.Grow(50000 * 20) // Заранее выделяем 1 МБ памяти одним куском!
```

* **Без `Grow()`:** 15–20 промежуточных переаллокаций буфера в куче.
* **С `Grow()`:** **Ровно 1 аллокация памяти на всю работу программы!**

## 5. Важнейшее правило безопасности: `Builder` нельзя копировать!

Поскольку `strings.Builder` выполняет unsafe-конвертацию внутреннего буфера в иммутабельную строку, рантайм защищает его от состояния гонки и дублирования буферов.

Внутри структуры `Builder` есть скрытое поле самопроверки `addr *Builder`:
```go
var b1 strings.Builder
b1.WriteString("test")

b2 := b1 // ОШИБКА В РАНТАЙМЕ!
b2.WriteString("crash") // ПАНИКА: strings: illegal use of non-zero Builder copied by value
```

> ⚠️ **Правило:** Никогда не передавай `strings.Builder` в функции по значению!  
> Если нужно передать билдер в другую функцию — **всегда передавай по указателю: `*strings.Builder`**.
