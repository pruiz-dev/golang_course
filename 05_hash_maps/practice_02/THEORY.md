# Теория: Итерация по Мапе и Умышленный Хаос

Обход элементов в мапе осуществляется с помощью всё того же цикла `for range`, с которым мы работали в массивах и слайсах.

```go
inventory := map[string]int{
    "Gold":   100,
    "Silver": 50,
    "Wood":   10,
}

for key, value := range inventory {
    fmt.Printf("%s: %d\n", key, value)
}
```

## Главная особенность: Рандомизация порядка
Если ты запустишь этот код несколько раз, ты заметишь странность: **порядок вывода элементов будет каждый раз разным**.

Сначала выведется `Gold, Silver, Wood`. 
При следующем запуске: `Wood, Gold, Silver`.

### Почему так происходит?
В большинстве других языков (например, старых версиях C++ или Java) порядок итерации хэш-таблиц был стабильным, но зависел от внутренней функции хэширования. Программисты часто замечали, что элементы выводятся в определенном предсказуемом порядке, и начинали писать бизнес-логику, которая **опиралась на этот порядок**.
Но как только разработчики языка обновляли алгоритм хэширования в новой версии языка, порядок элементов менялся, и у тысяч компаний внезапно ломался код в продакшене!

Чтобы защитить программистов от самих себя, создатели Go пошли на радикальный шаг: **они намеренно добавили рандомизатор в итерацию мап**. 
При каждом старте цикла `for range` по мапе, Go выбирает случайный начальный элемент. Это сделано специально, чтобы ты физически не мог написать код, зависящий от порядка ключей.

> **Золотое правило Go:** Мапа — это неупорядоченная коллекция. Никогда не закладывайся на порядок элементов при обходе мапы. Если тебе нужен строгий порядок вывода ключей, тебе придется сначала собрать все ключи в отдельный слайс `[]string`, отсортировать этот слайс, и уже по нему в цикле доставать значения из мапы.
