# Теория: Затенение (Shadowing) и ловушки короткого объявления `:=`

В Go существует два способа объявить переменную:
1. Ключевое слово `var` (например, `var x int = 5` или `var x int`).
2. Оператор короткого объявления `:=` (например, `x := 5`).

Короткое объявление `:=` очень удобно, компилятор сам выводит тип. Но именно в нем кроется одна из самых неприятных ловушек Go, которая называется **Shadowing (затенение переменных)**.

## Что такое область видимости (Scope)?
Область видимости — это блок кода, внутри которого переменная существует. Блоки обычно ограничиваются фигурными скобками `{ ... }`. В Go области видимости могут вкладываться друг в друга.

Пример:
```go
package main

import "fmt"

var globalVar = "Глобальная" // Пакетный scope (видна везде в пакете)

func main() { // Начало scope функции main
    var localVar = "Локальная" // Видна только внутри main
    
    if true { // Начало scope блока if
        var blockVar = "Блочная" // Видна только внутри if
        fmt.Println(localVar)    // Работает! (вложенный scope видит переменные внешнего)
    }
    // fmt.Println(blockVar) // Ошибка компиляции! blockVar уже не существует.
}
```

## Как работает Shadowing?
Проблема возникает, когда во вложенной области видимости ты объявляешь переменную с **таким же именем**, как и во внешней.

```go
package main

import "fmt"

func main() {
    x := 10 // Объявляем x в scope функции main

    if true {
        x := 20 // ОШИБКА В ЛОГИКЕ (хотя компилятор не ругается!)
        fmt.Println("Внутри if x =", x) // Выведет 20
    }

    fmt.Println("Снаружи if x =", x) // Выведет 10!
}
```

**Почему так произошло?**
Оператор `:=` означает **"создать новую переменную"**. Внутри блока `if` Go создал абсолютно новую, другую переменную `x`. Она "затенила" (shadowed) оригинальную `x`. Как только блок `if` закончился, эта новая `x` уничтожилась, а старая `x` осталась нетронутой.

### Частая ошибка на практике (с обработкой ошибок)

Самый частый баг с затенением в Go происходит при обработке ошибок:

```go
var data string
var err error

// ... где-то в коде ...

if true {
    // Функция GetData возвращает два значения (данные и ошибку).
    // Из-за того, что мы используем := , мы создаем НОВЫЕ переменные data и err внутри блока if.
    data, err := GetData() 
    if err != nil {
        return err
    }
    fmt.Println("Получили:", data)
}

// Оригинальная переменная data так и осталась пустой!
fmt.Println("Итоговые данные:", data) // Выведет пустую строку
```

## Множественное присваивание и нюансы `:=` против `=`

В Go можно присваивать (или объявлять) значения сразу нескольким переменным. И здесь кроется важнейшее отличие `:=` от `=`.

### Особенность `:=` (Исключение из правил)
Обычно, если переменная уже объявлена, повторное использование `:=` для нее вызывает ошибку компиляции. **НО есть исключение**: оператор `:=` сработает, если слева есть **хотя бы одна новая** переменная в **этой же** области видимости.

```go
a, b := 10, 20 // Создали a и b
a, c := 1, 2   // ОШИБКИ НЕТ! 'a' просто перезаписывается (получает 1), а 'c' создается с нуля (2).
```
Это спасает, когда функций много и они возвращают новые ошибки. **Но это работает безопасно только в рамках одного блока (scope)**. Если ты сделаешь это внутри вложенного блока (например, `if`), то правило "перезаписи" ломается: компилятор создаст новые локальные переменные, и оригинальная `a` окажется затененной.

### Особенность `=`
Оператор `=` **никогда не создает** новых переменных. Он только обновляет значения уже существующих. Он также поддерживает множественное присваивание:

```go
var x, y int
x, y = 5, 7 // Работает, обновляет x и y
```
Если ты попытаешься использовать `=` с переменной, которая еще не была объявлена через `var` или `:=`, компилятор выдаст ошибку `undefined`.

**Как избежать затенения на практике?**
Если у тебя уже есть переменная во внешнем блоке (например, `data`), а функция возвращает `data` и новую ошибку `err`, правильный подход — **объявить ошибку заранее**, чтобы можно было использовать строгий оператор `=` для обеих:

```go
var data string
var err error // Объявляем заранее, чтобы избежать использования :=

if true {
    // Используем =, потому что обе переменные уже известны компилятору.
    // Мы перезаписываем внешнюю data, затенения не происходит!
    data, err = GetData() 
}
```
