# База Знаний: Операция Среза (Slicing) — Двухиндексная и Трёхиндексная

## 1. Фундаментальная ментальная модель памяти

Чтобы раз и навсегда понимать любую операцию среза в Go, нужно различать две сущности:

1. **Базовый массив (Backing Array)** — физический непрерывный кусок оперативной памяти, где лежат реальные элементы.
2. **Срез (Slice / SliceHeader)** — маленькая легковесная структура фиксированного размера (24 байта на 64-битной архитектуре):
   * `Data uintptr` (8 байт) — прямой указатель на первый элемент окна в базовом массиве.
   * `Len  int`     (8 байт) — длина (сколько элементов сейчас видно через окно).
   * `Cap  int`     (8 байт) — ёмкость (сколько всего элементов доступно в базовом массиве от начала окна до конца массива).

```
Физический массив в памяти (например, [5]int):
Индексы:     0      1      2      3      4
Элементы:  [ 10 ] [ 20 ] [ 30 ] [ 40 ] [ 50 ]
              ▲      ▲
              │      └──────────┐
              │                 │
SliceHeader   │                 │
┌───────────────────────┐       │
│ Data: указатель ──────┼───────┘ (смотрит на элемент 20)
│ Len:  2               │         (видит 2 элемента: 20, 30)
│ Cap:  4               │         (до конца массива осталось 4 элемента: 20, 30, 40, 50)
└───────────────────────┘
```

> **Главное правило:** Сама по себе операция нарезки **НИКОГДА не копирует данные базового массива** и **НЕ создает новый массив в памяти**. Она лишь создает новый 24-байтовый заголовок `SliceHeader`, указывающий на нужную ячейку уже существующего массива.

## 2. Двухиндексная операция среза: `a[low : high]`

Синтаксис: `a[low : high]`, где:
* `low` — индекс первого элемента, который попадет в срез (включительно). Если опущен `a[:high]`, считается `low = 0`.
* `high` — индекс первого элемента, который **НЕ** попадет в срез (не включая его). Если опущен `a[low:]`, считается `high = len(a)`.
* Если опущены оба `a[:]`, срез охватывает все элементы.

### К чему применима двухиндексная операция?
1. **К обычному массиву фиксированного размера (`[N]T`)**:
   * На выходе: **срез `[]T`**.
   * Массив превращается в окно-слайс, смотрящее на этот массив.
2. **К срезу (`[]T`)**:
   * На выходе: **новый срез `[]T`**.
   * Создается новый заголовок, смотрящий на тот же базовый массив.
3. **К указателю на массив (`*[N]T`)**:
   * На выходе: **срез `[]T`** (Go автоматически разыменовывает указатель).
4. **К строке (`string`)**:
   * На выходе: **строка `string`** (НЕ срез байтов!).
   * Под капотом у строки свой заголовок `StringHeader` (16 байт: `Data` и `Len`, без `Cap`). Подстрока смотрит на те же неизменяемые байты.

---

### Как вычисляются `len` и `cap` при `a[low : high]`?

* **`len = high - low`**  
  (Количество элементов между левой и правой границей окна).
* **`cap = cap(a) - low`**  (для массива: `len(массива) - low`)  
  (Сколько элементов физически доступно от стартовой точки окна `low` до самого правого края базового массива).

#### Наглядный пошаговый пример:
Пусть у нас есть массив из 5 чисел:
```go
arr := [5]int{10, 20, 30, 40, 50}
s := arr[1:3]
```

Разбор формул:
1. `low = 1`, `high = 3`.
2. **Длина (Len):**
   `high - low = 3 - 1 = 2`
   Срез видит элементы с индексами `1` и `2` (значения `20` и `30`).
3. **Ёмкость (Cap):**
   Исходный массив имеет длину 5 (`cap(arr) = 5`).
   `cap(arr) - low = 5 - 1 = 4`
   Почему 4? Потому что начиная с ячейки `arr[1]` физически в массиве расположено ещё 4 ячейки: `20, 30, 40, 50`.

```
Массив arr:
Индекс:     0        1        2        3        4
Значение: [ 10 ]   [ 20 ]   [ 30 ]   [ 40 ]   [ 50 ]
                     ▲                 ▲        ▲
                     │◄─── Len = 2 ───►│        │
                     │                          │
                     │◄──────── Cap = 4 ───────►│
```

## 2.1. Интуитивные ментальные модели (чтобы уложилось в голове)

### Метафора «Забор и резы» (Почему `high` не включается?)
Главная путаница возникает из-за вопроса: *«Почему элемент с индексом `high` не попадает в срез?»*

Представь, что индексы `0, 1, 2, 3...` — это **не сами элементы**, а **перегородки между ними** (как деления на линейке или столбики забора):

```
Деления линейки:   0       1       2       3       4       5
                   |       |       |       |       |       |
Элементы:          |  10   |  20   |  30   |  40   |  50   |
```

Когда ты пишешь `[1 : 3]` — ты берешь ножницы и делаешь два разреза:
1. Первый рез — по риске **`1`** (сразу перед числом `20`).
2. Второй рез — по риске **`3`** (сразу после числа `30`).

Между риской `1` и риской `3` выпадают ровно два числа: **`20` и `30`**.
* Формула длины: `3 - 1 = 2` элемента. Всегда: правая риска минус левая риска.

---

### Метафора «Поезд и шторка на окне» (Как понять `Cap`)

Представь поезд с 5 вагонами:
```
Все вагоны (base):  [ 10 ]  [ 20 ]  [ 30 ]  [ 40 ]  [ 50 ]
```

Когда мы пишем `s1 := base[1:3]`:
1. Ты подошел к вагону **`20`** (индекс `1`).
2. Раздвинул шторку на окне так, что видно только **2 вагона**: `[20, 30]`. Это твой **`len = 2`**.
3. **Но остальные вагоны никуда не исчезли!** За твоей шторкой в сторону хвоста поезда стоят еще вагоны `[40]` и `[50]`.
4. Всего вагонов от тебя до тупика — **4 штуки**. Это твой **`cap = 4`**.

```
Поезд:           [ 10 ] | [ 20 ]   [ 30 ] | [ 40 ]   [ 50 ]
                        |                 |
Окошко (len=2):         └── видно эти ────┘
Вместимость (cap=4):    └── всего вагонов вправо: 4 штуки ──────┘
```

---

### Главная ловушка собеседований: Срез за пределами `len`, но внутри `cap`

Что произойдет, если написать:
```go
base := []int{10, 20, 30, 40, 50}
s1 := base[1:3] // len = 2, cap = 4
s2 := s1[2:4]   // Нарезаем s1 за пределами его len!
fmt.Println(s2)
```

Большинство разработчиков ошибочно ждут панику: *«Длина s1 равна 2, а мы берем срез [2:4]!»*.

Но рантайм Go выведет: **`[40 50]`**!

#### Секрет спецификации Go:
Операция среза `s[low:high]` проверяет границы **НЕ по `len`, а по `cap`**:
`0 <= low <= high <= cap(s)`

Пока `high <= cap`, шторку разрешено двигать дальше вправо по тому же базовому составу:
* Начало `s1` стояло на числе `20`.
* Смещение на 2 элемента вправо приводит нас на число **`40`**.
* Берем 2 элемента: **`[40, 50]`**.

> **Контраст со строками (`string`):**  
> У строки в `StringHeader` поля `Cap` нет вообще (только `Data` и `Len`).  
> Поэтому для строк `str[2:4]` при `len == 2` мгновенно вызывает панику: `slice bounds out of range`.

## 3. Ловушка двухиндексного среза: Скрытая порча памяти через `append`

Поскольку `cap` среза `s := arr[1:3]` равен `4`, а длина `len` равна `2`, рантайм Go видит, что **в ёмкости есть свободные слоты** (ячейки под индексами 3 и 4 массива `arr`).

Что произойдет, если вызвать `append`?
```go
arr := [5]int{10, 20, 30, 40, 50}
s := arr[1:3] // len = 2, cap = 4

s2 := append(s, 999)
```

1. Функция `append` проверяет: `len(2) < cap(4)` → место есть!
2. Go **НЕ создает новый массив**.
3. Go увеличивает длину и записывает `999` в следующую свободную ячейку базового массива (это индекс `1 + 2 = 3` в массиве `arr`):
   ```
   Массив arr стал: [ 10, 20, 30, 999, 50 ]  <-- элемент 40 был затерт!
   ```
4. Исходные данные в `arr` тихо испорчены!

## 4. Трёхиндексная операция среза: `a[low : high : max]` (Full Slice Expression)

Чтобы исключить скрытую порчу данных, в Go существует трёхиндексная форма с параметром `max`.

Синтаксис: `a[low : high : max]`, где:
* `low` — индекс начала окна.
* `high` — индекс конца окна.
* `max` — **индекс, ограничивающий ёмкость среза** (какой элемент базового массива считать потолком доступной памяти).

### К чему применима трёхиндексная операция?
1. **К массиву фиксированного размера (`[N]T`)**: → результат **срез `[]T`**.
2. **К срезу (`[]T`)**: → результат **срез `[]T`**.
3. **К указателю на массив (`*[N]T`)**: → результат **срез `[]T`**.
4. **К строкам (`string`) — ЗАПРЕЩЕНО!**
   * Компилятор выдаст ошибку: `invalid slice index: 3-index slice of string not allowed`.
   * Причина: у строк нет понятия ёмкости (`cap`), они иммутабельны, их нельзя расширять через `append`.

---

### Как вычисляются `len` и `cap` при `a[low : high : max]`?

* **`len = high - low`**
* **`cap = max - low`**

Обязательное условие компилятора:
`0 <= low <= high <= max <= cap(исходного)`

#### Наглядный пошаговый пример:
```go
arr := [5]int{10, 20, 30, 40, 50}
s := arr[1:3:3] // low=1, high=3, max=3
```

Разбор формул:
1. `low = 1`, `high = 3`, `max = 3`.
2. **Длина (Len):**
   `high - low = 3 - 1 = 2` (элементы 20 и 30).
3. **Ёмкость (Cap):**
   `max - low = 3 - 1 = 2` (мы искусственно заблокировали расширение среза!).

```
Массив arr:
Индекс:     0        1        2        3        4
Значение: [ 10 ]   [ 20 ]   [ 30 ]   [ 40 ]   [ 50 ]
                     ▲                 ▲
                     │◄─── Len = 2 ───►│
                     │◄─── Cap = 2 ───►│ (дальше смотреть запрещено!)
```

---

### Что происходит в памяти при `append` к трёхиндексному срезу?

```go
arr := [5]int{10, 20, 30, 40, 50}
s := arr[1:3:3] // len = 2, cap = 2

s2 := append(s, 999)
```

1. Функция `append` проверяет: `len(2) == cap(2)` → **свободного места нет!**
2. Go **вынужден выделить в куче совершенно новый независимый массив**.
3. Элементы `20, 30` копируются в новый массив, туда дописывается `999`.
4. Результат:
   * Исходный массив `arr` остался в сохранности: `[ 10, 20, 30, 40, 50 ]`.
   * Срез `s2` смотрит на новый кусок памяти: `[ 20, 30, 999 ]`.

## 5. Сводная сравнительная таблица

| Выражение | Что на входе | Что на выходе | Как считается `Len` | Как считается `Cap` | Влияние `append` на источник |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`arr[:]`** | `[N]T` или `[]T` | `[]T` | `len(arr)` | `cap(arr)` | Затрет элементы, если есть запас cap |
| **`arr[low:high]`** | Массив, срез, указатель на массив | `[]T` | `high - low` | `cap(исходного) - low` | ⚠️ **Опасно:** перезапишет данные базового массива |
| **`str[low:high]`** | Строка `string` | `string` | `high - low` | Нет cap у строк | Строки неизменяемы, append не применим |
| **`arr[low:high:max]`**| Массив, срез, указатель на массив | `[]T` | `high - low` | `max - low` | 🛡️ **Безопасно:** при `max == high` заставит `append` создать новый массив |
| **`str[low:high:max]`**| Строка `string` | ❌ Ошибка компиляции | — | — | Запрещено спецификацией языка |

## 6. Утечки памяти (Memory Leaks) при нарезке

Поскольку любой срез держит указатель `Data` на свой базовый массив, **сборщик мусора (GC) не имеет права освободить базовый массив целиком**, пока жив хотя бы один маленький срез, смотрящий на него.

```go
func readLogHeader() []byte {
    hugeLog := make([]byte, 100_000_000) // 100 МБ в памяти
    // ... прочитали данные ...
    return hugeLog[:10] // Возвращаем срез на 10 байт
}

func main() {
    header := readLogHeader()
    // ПЕРЕМЕННАЯ hugeLog УНИЧТОЖЕНА, НО:
    // header держит указатель на начало 100-мегабайтного массива.
    // Все 100 МБ остаются заблокированными в RAM!
}
```

### Как спасти память? Функция `copy()`
Чтобы освободить 100 МБ, нужно разорвать связь с исходным массивом:
```go
func readLogHeaderSafe() []byte {
    hugeLog := make([]byte, 100_000_000)
    // ...
    header := make([]byte, 10)
    copy(header, hugeLog[:10]) // Копируем сырые 10 байт в крошечный массив
    return header              // hugeLog (100 МБ) будет собран сборщиком мусора!
}
```
