# База Знаний: Нарезка (Slicing) и Утечки Памяти

## 1. Как Go идейно воспринимает Массивы и Слайсы
Чтобы навсегда закрыть этот вопрос, запомни главную метафору:
* **Массив** — это физическая земля (сырые байты, непрерывно лежащие в оперативной памяти).
* **Слайс** — это окно (или рамка), через которое ты смотришь на эту землю.

Под капотом **любого** слайса ВСЕГДА лежит массив. 
Когда ты пишешь `s := make([]int, 5)`, Go втайне от тебя создает в Куче безымянный массив на 5 элементов, а затем создает 24-байтовый слайс (окно), которое смотрит на этот безымянный массив.

### Превращение Массива в Слайс (`arr[:]`)
Если у тебя уже есть переменная-массив `arr := [5]int{1, 2, 3, 4, 5}`, и ты пишешь `s := arr[:]`, происходит следующее:
1. **Никакого дублирования памяти не происходит!**
2. Go мгновенно создает в памяти новую структуру `SliceHeader` (24 байта).
3. Указатель `Data` в этой структуре начинает указывать **ровно на то же самое место в памяти**, где лежит первый элемент твоего массива `arr`.
4. Теперь у тебя есть два способа управлять одной и той же памятью: через переменную `arr` или через слайс `s`. Изменишь `s[0] = 99` — оригинальный массив `arr` тут же изменится.

### Разница между `all := loot[:]` и `all := loot`
Если переменная `loot` — это *уже* слайс, то обе эти записи технически делают абсолютно одно и то же: они копируют 24-байтовый заголовок `SliceHeader`. Никакой разницы в производительности или памяти нет.
Однако синтаксис `[:]` почти всегда используется только в одном конкретном случае: **чтобы превратить жесткий Массив в Слайс**. Если `loot` — это массив `[5]int`, ты не можешь передать его туда, где требуется слайс. Но написав `loot[:]`, ты на лету создаешь "рамку", смотрящую на этот массив. 
Для переменных, которые уже являются слайсами, идиоматично и чисто писать просто `all := loot`.

## 2. Операция Нарезки (Slicing)
Синтаксис `[low:high]` позволяет создать новый слайс (новое окно), которое смотрит на уже существующий массив или слайс.

```go
loot := []string{"Золото", "Кинжал", "Броня", "Свиток", "Зелье"} // len=5, cap=5
weapons := loot[1:3] // ["Кинжал", "Броня"]
```

**Правило:** Нарезка (slicing) НИКОГДА не копирует сами данные. Она создает лишь новый 24-байтовый заголовок со смещенным указателем.

### Как вычисляется Capacity (cap) при нарезке?
Формула: `Новый_Cap = Старый_Cap - low`
В примере `hugeFile[:5]` (что равно `hugeFile[0:5]`), начальный индекс `low = 0`.
Следовательно, новый `cap` будет равен размеру всего оригинального массива (например, 1 000 000). 
Физическая память всё еще лежит впереди "окна", поэтому слайс всегда можно расширить вправо в пределах его `cap`.

## 3. Ловушка и Утечка Памяти (Memory Leak)
Поскольку слайсы — это всего лишь "окна", смотрящие на оригинальные массивы, они не дают сборщику мусора (Garbage Collector) удалять эти массивы из оперативной памяти.

**Классический пример утечки:**
```go
func getHeaderFromNetwork() []byte {
    hugeFile := make([]byte, 1000000) // Аллоцируем 1МБ в Куче
    // ... скачиваем файл ...
    return hugeFile[:5] // Возвращаем только "окно" на первые 5 байт
}

func main() {
    header := getHeaderFromNetwork() 
    // Функция отработала. Переменная hugeFile уничтожена.
    // НО! Слайс header всё еще держит указатель на начало мегабайтного массива.
    // Сборщик мусора НЕ МОЖЕТ удалить 1МБ памяти. Произошла скрытая утечка.
}
```
Крошечный слайс на 5 байт удерживает в Куче 1 миллион байт. Если такая функция вызывается часто, сервер быстро упадет с ошибкой `Out of Memory`.
