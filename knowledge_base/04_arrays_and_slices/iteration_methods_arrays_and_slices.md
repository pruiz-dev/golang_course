# База Знаний: Изолированные способы итерации (Массивы и Слайсы)

В Go обход массивов и обход слайсов синтаксически выглядят одинаково, но **под капотом работают абсолютно по-разному**. Главная проблема — невидимое копирование памяти.

---

## ЧАСТЬ 1: МАССИВЫ (Фиксированный размер `[N]T`)

Главное правило массивов: **они всегда передаются и присваиваются по значению (копируются целиком).**

### 1. `for i, v := range arr` (Чтение индекса и значения)
**Как работает:** Цикл `range` не работает с твоим оригинальным массивом. При старте цикла он создает **полную теневую копию** массива в памяти, и итерируется по этой копии.
**Применение:** Только для чтения небольших массивов.

```go
arr := [3]int{10, 20, 30}
// В этот момент Go аппаратно копирует все 24 байта массива arr во временную память.
for i, v := range arr { 
    // Изменяем саму локальную переменную `v`
    v = v + 5 // Оригинал не меняется
    
    // А что если мы изменим сам оригинал через индекс?
    if i == 0 {
        arr[1] = 999 
    }
    // Выведет: 10, 20, 30 (а не 999)!
    // Почему? Потому что цикл продолжает читать данные из своей скрытой стартовой копии, 
    // которая ничего не знает о том, что мы поменяли оригинальный arr[1].
    fmt.Println(v) 
}
```

### 2. `for _, v := range arr` (Только чтение значений)
То же самое, что и п.1, но мы отбрасываем индекс. Массив всё так же скрыто копируется целиком.
```go
arr := [3]int{10, 20, 30}
for _, v := range arr {
    fmt.Println(v)
}
```

### 3. `for i := range arr` (Обход по индексу для Мутации)
**Как работает:** Если мы опускаем `v` и оставляем только индекс `i`, оптимизатор компилятора Go умнеет. Он **перестает копировать весь массив**. Он просто генерирует счетчик `i`.
**Применение:** Золотой стандарт для изменения оригинального массива.
```go
arr := [3]int{10, 20, 30}
for i := range arr {
    arr[i] += 10 // Напрямую меняем оригинал по индексу!
}
// arr теперь [20, 30, 40]
```

### 4. `for i, v := range &arr` (Указатель на массив — Идеально для памяти)
**Вопрос:** *А зачем вообще итерироваться по указателю `&arr`, если можно использовать `for i := range arr` (который тоже не копирует массив, так как берет только индекс)?*
**Ответ:** Ты абсолютно прав, и это шикарный вопрос! 
Если массив находится прямо в этой же функции, ты можешь просто написать `for i := range arr` и внутри цикла обращаться к значениям как `val := arr[i]`. Это будет работать **абсолютно так же быстро** (массив не скопируется, копироваться будут только отдельные элементы на каждой итерации).

Использование `for i, v := range &arr` в пределах одной функции — это просто **синтаксическая эстетика**, чтобы не писать `arr[i]` руками, а получить готовое значение `v` сразу в заголовке цикла.

**Настоящая необходимость** использовать указатель возникает только в одном случае: 
* Когда огромный массив нужно **передать в другую функцию**. Если ты передашь его по значению `func Process(arr [10000]int)`, он скопируется еще на этапе вызова функции. Поэтому ты передаешь указатель `func Process(arrPtr *[10000]int)`, и уже внутри этой функции тебе нужно как-то его обойти. И вот тут `range` с его авто-разыменованием спасает ситуацию!

**Как работает:** Цикл `range` умеет автоматически разыменовывать указатели **только для жестких массивов**.
```go
func repairArmor(arrPtr *[4]int) {
    // range сам понимает, что это указатель, и обходит базовый массив
    for i := range arrPtr {
        // Синтаксический сахар: вместо (*arrPtr)[i] мы пишем просто arrPtr[i]
        // Go разыменовывает указатель под капотом.
        arrPtr[i] += 10 
    }
}
```

### 5. Классический цикл `for i := 0; i < len(arr); i++`
Работает так же, как и `for i := range arr`. Копирования массива не происходит. Используется, если нужен нестандартный шаг.
```go
arr := [4]int{1, 2, 3, 4}
for i := 0; i < len(arr); i += 2 { // Шаг 2
    fmt.Println(arr[i]) // Выведет 1 и 3
}
```

## ЧАСТЬ 2: СЛАЙСЫ (Динамические `[]T`)

Главное правило слайсов: **переменная слайса — это всего лишь структура на 24 байта (`SliceHeader`).** Сам скрытый массив лежит отдельно в Куче.

### 1. `for i, v := range slice` (Чтение)
**Как работает:** При старте цикла копируется **только заголовок слайса** (24 байта), а не скрытый массив с данными! Поэтому этот цикл всегда дешев по памяти, даже если в слайсе миллион элементов.
Переменная `v` — это копия значения.
```go
s := []int{10, 20, 30}
for i, v := range s {
    v += 5 // Оригинал не изменится!
}
```

### 2. `for _, v := range slice` (Только чтение значений)
Идеально для простого вывода данных на экран или агрегации.
```go
s := []int{10, 20, 30}
sum := 0
for _, v := range s {
    sum += v
}
```

### 3. `for i := range slice` (Обход по индексу для Мутации)
**Применение:** Лучший способ изменять значения скрытого массива. 
```go
s := []int{10, 20, 30}
for i := range s {
    s[i] += 10 // Оригинальные данные в Куче обновляются
}
```

### 4. Указатель на слайс `for i := range &slice` 
**Почему это не работает?** 
Синтаксический сахар (авто-разыменование в `range`) встроен в компилятор **только для жестких массивов**. 
Если ты попробуешь написать `for i := range &slice`, **код просто не скомпилируется** (ошибка: `cannot range over &slice`).

Создатели Go запретили это намерянно:
1. Переменная слайса весит всего 24 байта (`SliceHeader`). 
2. Нет абсолютно никакого смысла передавать указатель на слайс (`*[]int`), чтобы сэкономить 24 байта при вызове функции. 
3. Если ты хочешь изменить оригинальный массив, обычный слайс передается по значению, но его внутренний `Data`-указатель и так смотрит на оригинал в Куче.

Поэтому указатели на слайсы почти никогда не используются в Go, а `range` по ним запрещен на уровне языка.

## ЧАСТЬ 3: Новые фичи (Go 1.22)

### Обход целого числа (`for i := range N`)
Раньше, если тебе нужно было заполнить массив с нуля или выполнить действие N раз, ты писал классический цикл. С версии Go 1.22 язык научился принимать в `range` простые числа (`int`).

**Применение:** Инициализация массивов, генерация данных, повторение операций.
```go
// 1. Повторение без счетчика
for range 3 {
    fmt.Println("Hello!") // Выведет 3 раза
}

// 2. Инициализация массива индексами
var arr [5]int
for i := range 5 { // i будет принимать значения: 0, 1, 2, 3, 4
    arr[i] = i * 10
}
// Итог: [0, 10, 20, 30, 40]

// 3. Заполнение слайса
s := make([]int, 5)
for i := range 5 {
    s[i] = i * 10
}
```
