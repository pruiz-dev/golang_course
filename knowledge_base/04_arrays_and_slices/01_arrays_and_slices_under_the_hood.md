# База Знаний: Массивы, Слайсы и Анатомия Памяти

В этом документе собрана исчерпывающая теория о том, чем массивы отличаются от слайсов, и как именно они устроены под капотом на уровне процессора.

## 1. Массив (Array)
Массив имеет **фиксированную длину**, которая задается при создании. Длина массива является частью его типа (`[3]int` и `[5]int` — это два абсолютно разных типа данных).

### Что физически лежит внутри переменной-массива?
Если ты объявляешь массив, то **прямо внутри этой переменной** (в её ячейке памяти) физически лежат сами значения. Если у тебя `[3]int` на 64-битной системе, то переменная занимает ровно 24 байта (3 * 8). В ней нет никаких метаданных, указателей или структур. Только сырые данные.

- **Не инициализирован (Zero Value):** 
  ```go
  var a [3]int
  ```
  Go выделяет 24 байта под эту переменную и просто забивает их нулями на уровне процессора. Внутри переменной `a` физически лежит `[0, 0, 0]`. Она уже существует и готова к работе. Запись `a[0] = 10` просто перезапишет первые 8 байт.
- **Инициализирован:** 
  ```go
  a := [3]int{10, 20, 30}
  ```
  Внутри переменной `a` лежат именно эти три числа.

### Критическая особенность массивов
Поскольку внутри переменной лежат сами данные, при передаче массива в функцию (`func Do(arr [1000]int)`) язык копирует **всю переменную**. То есть физически дублирует все 1000 элементов в новую область памяти. Оригинал при этом не изменится, если менять данные внутри функции.

## 2. Адресация памяти: Как процессор находит элементы?
Возникает вопрос: если массив — это просто непрерывный кусок сырых данных (например, 40 байт для `[5]int`), как компилятор и процессор понимают, откуда начинать чтение, и как они находят нужный индекс?

### Фиксированный адрес (Смещение)
Имя переменной (`a`) существует только в исходном коде. В скомпилированном бинарнике имен нет. Во время компиляции Go вычисляет размер локальных переменных и жестко привязывает их к адресам на **Стеке (Stack Frame)**.
Если массив `a` находится в начале стека функции, компилятор заменяет все упоминания `a` на базовый адрес: *"Начало стека + 0 байт"*.

### Математика адресов (Индексы)
Процессору не нужно сканировать массив. Он использует математическую формулу **адресации со смещением (offset addressing)**:
`Адрес_Элемента = Стартовый_Адрес + (Индекс * Размер_Элемента)`

Например, для `a[3]` (где тип — `int` размером 8 байт):
1. Процессор берет стартовый адрес массива `a` (например, `0xAAA0`).
2. Умножает индекс `3` на `8 байт` = `24 байта`.
3. Прибавляет это к старту: `0xAAA0 + 24`.
4. Считывает 8 байт прямо по этому адресу.
Именно поэтому доступ по индексу работает мгновенно за `O(1)`.

## 3. Слайс (Slice)
Слайс — это **динамический** список. У него не указан размер в квадратных скобках.

### Что физически лежит внутри переменной-слайса?
Переменная-слайс — это НЕ сами данные. Переменная-слайс — это **всегда** крошечная встроенная структура (`SliceHeader`), которая весит ровно 24 байта (на 64-битных системах). Внутри ячейки памяти этой переменной лежат строго три поля (по 8 байт каждое):
1. `Data` — указатель на реальный скрытый массив, где лежат данные.
2. `Len` — текущая длина.
3. `Cap` — вместимость (сколько памяти выделено "про запас").

- **Не инициализирован (Zero Value):**
  ```go
  var s []int
  ```
  Go выделяет 24 байта под переменную `s` и заполняет её нулями. Получается структура:
  - `Data = nil` (адрес `0x00000000`)
  - `Len = 0`
  - `Cap = 0`
  
  > **Важно:** Сама эта структура **не равна `nil`**. Переменная `s` существует аппаратно и занимает 24 байта. Но в Go есть синтаксический сахар: если поле `Data` равно `nil`, то проверка `s == nil` вернет `true`. 
  
  Так как указатель пуст, попытка записи `s[0] = 10` приведет к панике. Добавлять данные можно только через `append()`.

- **Инициализирован:**
  ```go
  s := []int{10, 20}
  ```
  Go глубоко в Куче создает скрытый массив `[10, 20]`, а внутрь твоей переменной `s` записывает:
  - `Data = 0xc000...` (адрес этого скрытого массива)
  - `Len = 2`
  - `Cap = 2`

### Критическая особенность слайсов
Когда ты передаешь слайс в функцию, копируется **только переменная `s`** (та самая 24-байтовая структура `SliceHeader`). Указатель `Data` внутри скопированной структуры продолжает смотреть на тот же самый скрытый массив в Куче. Поэтому изменение данных через копию отразится на оригинале.

### Создание слайса через `make()`: Разница сигнатур и Практические Кейсы
Встроенная функция `make` позволяет сразу выделить память под скрытый массив слайса в Куче. Она умеет принимать два или три аргумента:

1. **Три аргумента: `make([]byte, 0, 5)`**
   Здесь ты явно говоришь: «Сделай мне пустой слайс (длина `0`), но выдели память под `5` элементов (вместимость `5`)». 
   **Практический кейс:** Предварительная аллокация памяти (Pre-allocation) перед циклом `append`. 
   Например, ты делаешь запрос в базу данных, который вернет максимум 1000 строк. Из них тебе нужно отфильтровать только активных пользователей. Ты не знаешь их точное количество, но их точно не больше 1000. Ты делаешь `result := make([]User, 0, 1000)`, а затем в цикле добавляешь подходящих: `result = append(result, user)`. Поскольку память уже выделена, `append` отработает максимально быстро, без дорогих операций перевыделения Кучи.

2. **Два аргумента: `make([]byte, 5)`**
   Если ты не передаешь третий аргумент (вместимость), Go считает, что вместимость равна длине. Эта запись эквивалентна `make([]byte, 5, 5)`. 
   В этом случае Go **мгновенно заполняет этот слайс "нулевыми значениями"**. То есть он сразу создает скрытый массив из 5 элементов (например, `[0, 0, 0, 0, 0]`). 
   **Практические кейсы:** 
   - **Приемник для `copy`:** Как мы разбирали в теме утечек памяти, целевой слайс `dst` обязан иметь физическую длину `len`, чтобы в него аппаратно скопировались байты из функции `copy(dst, src)`.
   - **Буфер для чтения (IO):** Когда ты читаешь данные из файла или по сети TCP-сокетом, тебе нужен готовый кусок памяти (буфер), куда операционная система запишет байты. Ты делаешь `buf := make([]byte, 1024)` и передаешь его в функцию чтения `file.Read(buf)`.
   - **Параллельная запись (Concurrency):** Если 10 горутин должны вычислить результаты и положить их в слайс по своим индексам (каждая в свою ячейку от 0 до 9), ты заранее создаешь `res := make([]int, 10)`. Каждая горутина пишет в `res[i]`, не мешая друг другу. Если бы ты использовал `append`, горутины подрались бы за право расширить слайс (Race Condition).
