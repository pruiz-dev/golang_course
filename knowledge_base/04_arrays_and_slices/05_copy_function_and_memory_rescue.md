# База Знаний: Спасение памяти через функцию `copy()`

## 1. Проблема нарезки (Slicing)
В предыдущей статье мы выяснили, что нарезка слайса (`hugeFile[:5]`) не копирует данные физически, а просто создает новый 24-байтовый заголовок, который смотрит на старый гигантский массив.
Это приводит к утечке памяти: крошечный слайс-окно не дает сборщику мусора удалить из оперативной памяти огромный файл, потому что на него всё еще есть ссылка.

## 2. Спасение через физическое копирование
Чтобы "отвязать" нужный кусочек данных от огромного мусорного массива, данные нужно **физически скопировать** в абсолютно новый, независимый участок памяти. 

Для этого в Go используется встроенная функция `copy(dst, src)` (скопировать из `src` в `dst`).

### Как это выглядит в коде:
```go
func getHeaderFromNetwork() []byte {
    hugeFile := make([]byte, 1000000) // Аллоцируем 1МБ в Куче

    // 1. Создаем абсолютно новый, независимый массив на 5 элементов.
    // Используем make с ДВУМЯ аргументами, чтобы len сразу был равен 5.
    safeHeader := make([]byte, 5) 

    // 2. Физически копируем 5 байт из старого массива в новый.
    copy(safeHeader, hugeFile)

    // 3. Возвращаем независимую копию.
    return safeHeader
}
```

**Что происходит при вызове `copy`?**
1. Вызов `make([]byte, 5)` аллоцирует в Куче совершенно новый независимый массив на 5 ячеек памяти.
2. Функция `copy` аппаратно переносит 5 байт из гигантского массива `hugeFile` в этот новый 5-байтовый массив `safeHeader`.
3. Теперь `safeHeader` смотрит на свой собственный маленький массив (у него `cap = 5`).
4. Когда функция завершится, на огромный массив `hugeFile` больше не останется ни одной ссылки. Garbage Collector (Сборщик мусора) радостно удалит 1 Мегабайт памяти!

## 3. Главная ловушка функции `copy`
Самая частая ошибка новичков при использовании `copy` связана с непониманием того, сколько элементов будет скопировано.

**Функция `copy` копирует ровно `min(len(dst), len(src))` элементов (минимум из двух длин).**

* **Неправильно:**
  ```go
  dst := make([]byte, 0, 5) // len = 0, cap = 5
  copy(dst, hugeFile)
  ```
  Функция сравнит длины: `min(0, 1000000) = 0`. В итоге скопируется ровно **Ноль** байт! Массив останется пустым.

* **Правильно:**
  ```go
  dst := make([]byte, 5) // len = 5, cap = 5 (заполнен нулями)
  copy(dst, hugeFile)
  ```
  Функция сравнит длины: `min(5, 1000000) = 5`. Скопируется 5 байт (они перезапишут исходные нули). Целевой слайс-приемник `dst` всегда должен быть предварительно "растянут" на нужную длину, чтобы в него физически влезли копируемые элементы.
