# База Знаний: Переменные и Типы данных (Абсолютные азы)

Этот документ содержит собранную теорию, инсайты и ответы на вопросы, возникшие в ходе прохождения темы `01_variables_and_types`.

## 1. Структура проекта: Модули, Папки и Пакеты

В Go строгая иерархия файловой системы, которая напрямую влияет на компиляцию:

* **Модуль (Проект)**: Инициализируется командой `go mod init <name>`. Создает файл `go.mod`, который является паспортом проекта. Здесь фиксируется корневой путь и зависимости.
* **Папка = Пакет**: Все `.go` файлы, лежащие в одной директории, обязаны принадлежать к одному пакету. Нельзя в одной папке иметь файлы с `package main` и `package utils` — компилятор выдаст ошибку. Если нужно вынести код в пакет `t`, нужно создать подпапку `t`.
* **`package main`**: Зарезервированное имя пакета. Оно указывает компилятору, что из этого пакета нужно собрать исполняемый бинарный файл (в нем должна быть функция `main()`). Любой другой пакет считается библиотекой.

### Пример: Взаимодействие разных пакетов
Если у тебя есть два файла с разными пакетами, они обязаны лежать в разных папках. Чтобы `main` мог использовать код из другого пакета, его нужно **импортировать**, а функции внутри библиотеки должны начинаться с **Заглавной буквы** (чтобы быть публичными/экспортируемыми).

Структура проекта:
```text
practice_01/
├── go.mod        // module practice_01
├── main.go       // package main
└── t/
    └── lib.go    // package t
```

**t/lib.go** (Библиотека):
```go
package t

import "fmt"

// Название с большой буквы - функция доступна другим пакетам (экспортируется)
func PrintHello() {
    fmt.Println("Привет из пакета t!")
}
```

**main.go** (Точка входа):
```go
package main

import (
    "practice_01/t" // Импорт по пути: имя_модуля/название_папки
)

func main() {
    t.PrintHello() // Вызываем функцию из пакета t
}
```
При запуске `go run .` из папки `practice_01` (где лежит `main`), компилятор сам увидит импорт `"practice_01/t"`, пойдет в эту папку, скомпилирует `lib.go` и сошьет всё это в один цельный исполняемый файл.

### Как работает `go run .`?
Точка означает "текущая директория". Компилятор собирает **все** `.go` файлы в этой папке, объединяет их в одну программу, компилирует во временный файл, запускает его и затем удаляет. Благодаря этому файлы `main.go` и `analyzer.go`, находящиеся в одном пакете `main`, видят функции друг друга без явных импортов.

## 2. Размеры базовых типов в памяти

При использовании пакета `unsafe` и функции `Sizeof` можно узнать реальный размер переменной в байтах.

* `int32`: всегда 4 байта.
* `int64`: всегда 8 байт.
* `bool`: всегда 1 байт (так удобнее для адресации памяти процессором, хотя логически нужен 1 бит).

### Почему размер `int` плавающий?
Размер типа `int` зависит от разрядности процессора (целевой архитектуры компиляции):
* На 64-битных системах `int` занимает 8 байт (64 бита).
* На 32-битных системах `int` занимает 4 байта (32 бита).

Тип `int` создан для максимальной скорости работы. Процессору удобнее и быстрее всего оперировать данными, размер которых совпадает с размером его машинного слова (внутреннего регистра). 

### Как `int64` работает на 32-битной архитектуре?
Даже если процессор 32-битный, использование `int64` гарантирует 8 байт в памяти. Однако для выполнения математических операций компилятор вынужден генерировать программную эмуляцию: одно 64-битное число разбивается на два 32-битных куска, и сложение происходит в два этапа (младшие биты, затем старшие с учетом переноса). Это работает, но **снижает производительность** из-за дополнительных тактов процессора.

## 3. Строки под капотом (StringHeader)

Независимо от длины строки (будь то пустая строка `""` или длинный текст), `unsafe.Sizeof` для переменной типа `string` возвращает **16 байт** (на 64-битной системе).

Это происходит потому, что строка в Go — это не массив символов напрямую, а структура-дескриптор `StringHeader`:
```go
type StringHeader struct {
    Data uintptr // Указатель на адрес памяти, где реально лежат символы (8 байт)
    Len  int     // Длина строки (8 байт)
}
```
Функция `unsafe.Sizeof` измеряет размер самой "коробочки" (`StringHeader`), а не памяти, на которую указывает `Data`. Для пустой строки `Data` равен `nil`, а `Len` равен `0`, но сама структура всё равно занимает 16 байт.

## 4. Ошибки и плохие практики (Code Review Insights)
* **Избыточное приведение типов**: В Go не нужно явно приводить переменную к её же собственному типу. Это визуальный шум.
  *Плохо:* `PrintInt32Info(int32(v32Int))` (если `v32Int` уже `int32`).
  *Хорошо:* `PrintInt32Info(v32Int)`.
