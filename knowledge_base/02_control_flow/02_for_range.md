# База Знаний: Цикл for и ловушки for range

Этот документ представляет собой исчерпывающую шпаргалку по единственному в Go циклу `for`, а также детальный разбор коварных ловушек конструкции `for range`. Подготовлено для прохождения собеседований и уверенной работы в продакшене.

В Go решили отказаться от зоопарка циклов (нет `while`, нет `do-while`). Вместо этого есть только один универсальный цикл — `for`.

## 1. Классический цикл
Работает так же, как в C/C++ или Java: состоит из блока инициализации, условия и пост-действия.
```go
for i := 0; i < 5; i++ {
    fmt.Println(i)
}
```

## 2. Аналог `while`
Если убрать блок инициализации и пост-действие, цикл `for` элегантно превращается в `while`:
```go
for condition == true {
    // Выполняется, пока условие истинно
}
```
А если убрать вообще все условия, получится бесконечный цикл `for { ... }` (аналог `while (true)`).

## 3. Магия `for range`
Самый частый способ итерирования по массивам, слайсам, строкам и мапам — это конструкция `range`.
Важнейшее правило: `range` всегда возвращает **два значения**:
1. Индекс (или ключ для мапы).
2. Копию значения (самого элемента).

```go
nums := []int{10, 20, 30}
for index, value := range nums {
    fmt.Printf("Индекс: %d, Значение: %d\n", index, value)
}
```
* **Игнорирование значения:** Если нужен только индекс, второе значение можно просто не писать: `for i := range nums`.
* **Игнорирование индекса:** Если нужно только значение, индекс нужно явно проигнорировать с помощью пустого идентификатора (blank identifier `_`): `for _, v := range nums`.

## 4. Ловушка №1: Изменение по копии (Value semantic)
Это самая частая ошибка разработчиков, переходящих с других языков. Переменная `value` в конструкции `for _, value := range ...` — это **копия** реального элемента из исходной коллекции.

Если попытаться изменить `value` внутри цикла, исходный массив или слайс **никак не изменится**:
```go
users := []string{"Alice", "Bob"}
for _, user := range users {
    user = "Hacked!" // ОШИБКА: Меняем только локальную, временную копию переменной user!
}
// Слайс users остался ["Alice", "Bob"]
```
**Архитектурное исправление:** Чтобы изменить оригинальные данные, необходимо отбросить копию и обращаться к элементам массива напрямую по их индексу (в памяти):
```go
for i := range users {
    users[i] = "Hacked!" // Идеально. Прямой доступ к ячейке памяти.
}
```

## 5. Легендарная Ловушка №2: Указатель на переменную цикла
До версии Go 1.22 цикл `for range` имел серьезный архитектурный нюанс, который был причиной тысяч багов в многопоточном продакшен-коде.

Компилятор создавал переменную цикла (`value`) **всего один раз** перед запуском цикла, а затем на каждой итерации просто перезаписывал в эту же ячейку памяти новое значение.
Если разработчик пытался сохранить *адрес памяти* (`&value`) этой переменной (например, клал указатели в другой массив или запускал асинхронные горутины, передавая туда этот указатель), то в итоге **все сохраненные указатели смотрели на одну и ту же ячейку памяти**. В этой ячейке всегда оставалось значение из **самой последней итерации**.

*Историческая справка:* Начиная с Go 1.22 (февраль 2024 года), эту логику наконец-то исправили. Теперь переменная цикла пересоздается заново на каждой итерации, и взятие указателя на нее абсолютно безопасно. Однако на технических собеседованиях этот вопрос ("Что выведет код с горутинами в цикле?") до сих пор является классической лакмусовой бумажкой на понимание истории языка и механики аллокации памяти.
