# База Знаний: Метки (Labels) и выход из вложенных циклов

Этот документ исчерпывающе описывает механизм работы меток (Labels) в Go, который позволяет элегантно управлять вложенными циклами без использования костылей.

Иногда алгоритм требует использования вложенных циклов (цикл внутри цикла). Классический пример: поиск конкретного элемента в двумерном массиве (матрице) или перекрестная проверка данных.

## Проблема `break` во вложенных циклах
Ключевое слово `break` прерывает только **тот цикл, внутри которого оно вызвано**.

```go
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if j == 1 {
            break // Этот break выйдет только из внутреннего цикла (j). Внешний (i) продолжит работу!
        }
    }
}
```
В старых языках (Java, C, C++) разработчикам часто приходилось заводить переменные-флаги (например, `found := true`), чтобы проверять их во внешнем цикле и делать двойной `break`. Это плодит грязный "спагетти-код".

## Решение: Использование меток (Labels)
Go предлагает элегантное и мощное решение — **метки (Labels)**. 
Ты можешь дать имя любому циклу, написав слово и двоеточие прямо перед ним. А затем передать это имя команде `break` или `continue`.

```go
OuterLoop: // Это метка для внешнего цикла
for i := 0; i < 5; i++ {
    for j := 0; j < 5; j++ {
        if i == 2 && j == 2 {
            fmt.Println("Нашли нужный элемент, выходим вообще из всех циклов!")
            break OuterLoop // Прерывает цикл, помеченный как OuterLoop
        }
    }
}
```

### `continue` с метками
Метки работают и с `continue`. Если во внутреннем цикле ты сделаешь `continue OuterLoop`, программа немедленно прервет текущую итерацию внутреннего цикла и прыгнет на **следующую итерацию внешнего цикла**. Это крайне полезно при фильтрации данных (например, если элемент внутреннего цикла забраковал всю строку матрицы, и нужно сразу переходить к следующей строке).

### Важное отличие от `goto`
> **Важно:** Метки в Go для `break`/`continue` не имеют ничего общего с опасным оператором `goto`. 
> `break Label` можно использовать **только** для выхода из иерархии вложенных блоков (циклов, `switch` или `select`). Он не позволяет прыгать в произвольное место кода (что могло бы сломать логику выполнения и повредить стек памяти), поэтому это абсолютно безопасный, идиоматичный и рекомендуемый подход.

## Ловушки `break` и `continue` внутри `switch`

При использовании `switch` внутри цикла `for` поведение операторов управления часто сбивает с толку, так как у них разные "зоны поражения".

### 1. Как работает `break`
По умолчанию в Go ключевое слово `break` прерывает **ближайший к нему допустимый блок**. 
Согласно спецификации языка Go, `break` может прерывать **только три конструкции**: `for`, `switch` и `select`. (К простому блоку или `if` его применить нельзя).

Поэтому, если ты напишешь обычный `break` внутри `case` оператора `switch`, программа убьет именно сам `switch` (как ближайший допустимый блок) и спокойно пойдет на следующую итерацию внешнего цикла `for`!

```go
for i := 0; i < 5; i++ {
    switch i {
    case 2:
        break // ОШИБКА (если цель выйти из цикла): Прервет ТОЛЬКО switch. Цикл продолжит работу.
    }
}
```
**Решение:** Использование меток — единственный способ корректно прервать внешний цикл изнутри `switch` (например, `break Loop`).

### 2. Как работает `continue`
В отличие от `break`, оператор `continue` по спецификации Go может применяться **ТОЛЬКО к циклам (`for`)**. Он вообще не умеет воздействовать на `switch` или `select`.

Поэтому, если ты используешь `continue` внутри `case` оператора `switch`, компилятор абсолютно законно "простреливает" `switch` насквозь и применяет `continue` к ближайшему внешнему циклу `for`, немедленно завершая его текущую итерацию и переходя к следующей.

```go
for i := 0; i < 5; i++ {
    switch i {
    case 2:
        continue // Мгновенно прервет текущую итерацию внешнего цикла for и перейдет к i=3
    }
}
```
Это поведение очень удобно использовать для быстрой фильтрации элементов внутри `switch`, но о нем нужно помнить, чтобы не перепутать с `break`.

## Идиоматичный перебор индексов массива
Во время прохождения практики мы закрепили важное правило идиоматичного синтаксиса Go. 
Если при обходе массива в цикле тебе нужны только его индексы, **не нужно** использовать функцию `len()`:
* *Не идиоматично (хоть и работает в Go 1.22+):* `for i := range len(mapGrid)`
* *Идиоматично (Best Practice):* `for i := range mapGrid`

Движок Go сам под капотом понимает, что если ты запрашиваешь только одну переменную при вызове `range`, он должен вернуть список индексов элементов от `0` до `длины коллекции - 1`. Вызов `len()` здесь избыточен и только загрязняет код.
