# База Знаний: Переменные, Типы данных и Область видимости

Этот документ содержит собранную теорию, инсайты и ответы на вопросы, возникшие в ходе прохождения темы `01_variables_and_types`.

## 1. Размеры базовых типов в памяти

При использовании пакета `unsafe` и функции `Sizeof` можно узнать реальный размер переменной в байтах.

* `int32`: всегда 4 байта.
* `int64`: всегда 8 байт.
* `bool`: всегда 1 байт (так удобнее для адресации памяти процессором, хотя логически нужен 1 бит).

### Почему размер `int` плавающий?
Размер типа `int` зависит от разрядности процессора (целевой архитектуры компиляции):
* На 64-битных системах `int` занимает 8 байт (64 бита).
* На 32-битных системах `int` занимает 4 байта (32 бита).

Тип `int` создан для максимальной скорости работы. Процессору удобнее и быстрее всего оперировать данными, размер которых совпадает с размером его машинного слова (внутреннего регистра). 

### Как `int64` работает на 32-битной архитектуре?
Даже если процессор 32-битный, использование `int64` гарантирует 8 байт в памяти. Однако для выполнения математических операций компилятор вынужден генерировать программную эмуляцию: одно 64-битное число разбивается на два 32-битных куска, и сложение происходит в два этапа. Это работает, но **снижает производительность** из-за дополнительных тактов процессора.

## 2. Строки под капотом (StringHeader)

Независимо от длины строки (будь то пустая строка `""` или длинный текст), `unsafe.Sizeof` для переменной типа `string` возвращает **16 байт** (на 64-битной системе).

Это происходит потому, что строка в Go — это не массив символов напрямую, а структура-дескриптор `StringHeader`:
```go
type StringHeader struct {
    Data uintptr // Указатель на адрес памяти, где реально лежат символы (8 байт)
    Len  int     // Длина строки (8 байт)
}
```
Функция `unsafe.Sizeof` измеряет размер самой "коробочки" (`StringHeader`), а не памяти, на которую указывает `Data`.

## 3. Ошибки и плохие практики (Code Review Insights)
* **Избыточное приведение типов**: В Go не нужно явно приводить переменную к её же собственному типу. Это визуальный шум.
  *Плохо:* `PrintInt32Info(int32(v32Int))` (если `v32Int` уже `int32`).
  *Хорошо:* `PrintInt32Info(v32Int)`.

## 4. Области видимости (Scope) и Затенение (Shadowing)

**Shadowing (затенение)** — это ситуация, когда переменная во вложенном блоке (scope) создается с таким же именем, как и во внешнем блоке, перекрывая ("затеняя") к ней доступ.

Самая частая причина затенения — неаккуратное использование короткого объявления `:=` внутри вложенных блоков (например, в `if`).

### Исключение оператора `:=`
Обычно `:=` запрещено применять к уже существующей переменной. Но есть правило: **`:=` разрешен, если слева есть хотя бы одна новая переменная в текущем блоке.**

```go
// Множественное присваивание с созданием новой переменной (в одном scope):
age, isActive := 20, false
age, newStatus := getStats() // ОШИБКИ НЕТ! age просто обновляется, newStatus создается.
```

### Как возникает баг?
Если мы делаем то же самое, но во вложенном блоке, компилятор создает **новые** локальные переменные, а внешние не трогает.

```go
var currentUser string
var err error // Объявляем err заранее во внешнем scope

if true {
    // ВАЖНО: Используем строгое '=', чтобы обновить внешние переменные!
    // Если бы мы написали 'currentUser, err := fetchUser()',
    // то создались бы две абсолютно новые локальные переменные внутри if,
    // и внешняя currentUser осталась бы пустой.
    currentUser, err = fetchUser()
}
```

## 5. Конвертация типов и Переполнение (Overflow)

В Go строгая типизация, поэтому компилятор не производит неявных преобразований.

### Знаковые числа и Дополнительный код (Two's complement)
Для знаковых типов (например, `int8`) старший (самый левый) бит отвечает за знак: `0` — плюс, `1` — минус.
Положительные числа считаются от `00000000` (0) до `01111111` (127).
Если прибавить 1 к `127`, бинарное сложение даст `10000000`. Процессор интерпретирует это как отрицательное число (`-128`). Переполнение вызывает скачок на другой конец числовой оси.

### Усечение (Truncation)
При явном приведении из большего типа в меньший (например, `int16` -> `int8`), Go не проверяет, помещается ли значение. Он просто безжалостно **отрезает старшие биты**.
Например, число `1000` в `int16` выглядит так: `00000011 11101000`.
При касте в `int8` отрезается левая половина (1 байт), остается только хвост `11101000`. Это число `-24`.

### Нетипизированные константы
Компилятор может спасти от переполнения только при работе с **нетипизированными константами**. Если написать `var a int8 = 300`, компилятор на этапе сборки поймет, что число не влезает в 8 бит, и выдаст ошибку `overflows int8`. Но он бессилен, если приведение типов происходит над переменными во время работы программы (runtime).

## 6. Пустой идентификатор (Blank Identifier) "_"
В Go есть строгое правило: **любая объявленная локальная переменная обязана быть использована**. Если переменная создана, но нигде в коде не читается, компилятор выдаст ошибку (`declared and not used`).

Если функция возвращает результат, мы можем вообще не присваивать его никуда, просто написав `CreateValue()`. Компилятор это проглотит (значение просто исчезнет). 
Однако, в Go есть правило хорошего тона (и требования строгих линтеров): если функция возвращает важные данные (особенно ошибки), лучше использовать пустой идентификатор `_` (черную дыру). Запись `_ = CreateValue()` **явно** показывает читателю кода: *"Я знаю, что функция возвращает значение, и я намеренно его выбрасываю, я не забыл про него"*.

### Почему мы пишем `_ =` (а не `_ :=`)?
В этом кроется важнейшее понимание работы операторов:
* **`:=` (Создать и присвоить):** Выделяет новую память на стеке и дает ей имя.
* **`=` (Присвоить):** Кладет данные в **уже существующее** место.

Черная дыра `_` — это не переменная. Под неё не выделяется оперативная память. Это встроенный концепт языка, который существует всегда. Поскольку мы не можем "создать" черную дыру, мы не можем применить к ней оператор `:=`. Мы можем только сбросить (присвоить `=`) в неё данные:
```go
_ = CreateValue() // Правильно. Результат улетает в никуда.
// _ := CreateValue() // ОШИБКА! Слева нет новых переменных для создания.
```

**Исключение:** Оператор `:=` можно использовать с `_`, если функция возвращает несколько значений, и хотя бы одно из них мы сохраняем в **новую** переменную:
```go
result, _ := GetData() // Работает! Оператор := создает новую переменную result, а ошибку сбрасывает в _.
```
