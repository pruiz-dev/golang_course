# База Знаний: Работа с типом byte, бинарными потоками и протоколами

## 1. Фундамент: Что такое `byte` в Go?

В Go тип `byte` — это не самостоятельный тип данных, а встроенный псевдоним (alias) для беззнакового 8-битного целого числа:

```go
type byte = uint8
```

### Ключевые свойства `byte`:
1. **Диапазон значений:** от `0` до `255` (ровно 256 возможных состояний, 8 бит).
2. **Литералы символов:** запись `'A'` — это просто синтаксический сахар для десятичного числа `65` или шестнадцатеричного `0x41`.
3. **Шестнадцатеричная запись (HEX):** в сетевых протоколах и бинарных форматах принято записывать байты как `0x00`, `0xAA`, `0xFF`, потому что один байт компактно и однозначно описывается двумя шестнадцатеричными цифрами (`0x00`..`0xFF`).

## 2. Байты против Рун: Разница на уровне представления

| Характеристика | `byte` (`uint8`) | `rune` (`int32`) |
| :--- | :--- | :--- |
| **Размер в памяти** | **1 байт** (8 бит) | **4 байта** (32 бита) |
| **Диапазон** | `0 .. 255` | `0 .. 0x10FFFF` (весь Unicode) |
| **Назначение** | Сырые бинарные данные, ASCII-текст, сетевые пакеты | Кодовая точка Unicode (символы любого языка, эмодзи) |
| **Спецификатор `%v`** | Печатает десятичное число (`65`) | Печатает десятичный код Unicode (`128293`) |
| **Спецификатор `%c`** | Печатает ASCII-символ (`'A'`) | Печатает реальный символ/эмодзи (`'🔥'`) |
| **Спецификатор `% X`** | Шестнадцатеричный байт (`41`) | Дамп физических байтов UTF-8 (`F0 9F 94 A5`) |

> **Ловушка форматирования:**  
> Если передать руну `r` в `fmt.Printf("%x", r)`, Go напечатает 32-битную кодовую точку Unicode (`1f525`), а не физические байты UTF-8.  
> Чтобы увидеть реальные сетевые байты символа в UTF-8, руну нужно упаковать в срез байт: `fmt.Printf("% X", []byte(string(r)))`.

## 3. Потоковый буфер `bytes.Buffer` под микроскопом

Для сборки и разбора смешанных (бинарно-текстовых) пакетов стандартная библиотека предоставляет `bytes.Buffer`.

### Конструктор с нулевыми аллокациями: `bytes.NewBuffer`
* **Антипаттерн:**
  ```go
  var bb bytes.Buffer
  bb.WriteString(string(b)) // Лишняя аллокация: []byte -> string -> []byte
  ```
* **Идиоматичный подход Middle:**
  ```go
  bb := bytes.NewBuffer(b) // 0 аллокаций памяти! Буфер оборачивает срез b на месте.
  ```

### Методы записи:
1. **`buf.WriteByte(b byte)`:** дописывает ровно 1 физический байт (число 0..255).
2. **`buf.WriteString(s string)`:** дописывает байты строки.
3. **`buf.WriteRune(r rune)`:** кодирует 32-битную руну в от 1 до 4 байт UTF-8 и дописывает их в хвост.
4. **`buf.Bytes() []byte`:** возвращает срез накопленных байтов без копирования.

### Методы пошагового чтения:
1. **`buf.ReadByte() (byte, error)`:** вычитывает 1 байт и сдвигает внутреннее смещение `off += 1`.
2. **`buf.ReadBytes(delim byte) ([]byte, error)`:** читает поток вперед до первого байта-разделителя (например, до `0x00`), включая его.
3. **`buf.ReadRune() (r rune, size int, err error)`:** читает префиксные биты, определяет длину символа, декодирует UTF-8, сдвигает `off += size` и возвращает руну.

## 4. Как рантайм Go обрабатывает поврежденный UTF-8

### Анатомия байтов UTF-8:
* **ASCII (1 байт):** старший бит 0 (`b < 128` или `b & 0x80 == 0`).
* **Ведущий байт (Lead Byte):**
  - 2 байта: `110xxxxx` (`192..223`)
  - 3 байта: `1110xxxx` (`224..239`)
  - 4 байта: `11110xxx` (`240..247`)
* **Байт продолжения (Continuation Byte):**
  - `10xxxxxx` (`128..191`). Одиночный байт продолжения без ведущего байта перед ним — это ошибка кодировки.

### Ловушка метода `ReadRune()`:
Когда `ReadRune()` встречает в потоке поврежденный байт (например, одиночный `0x9F`):
* Он **НЕ возвращает ошибку `err != nil`**!
* Он возвращает специальную константу **`utf8.RuneError`** (значение `0xFFFD`, в десятичной системе `65533`).
* При этом возвращается размер `size = 1` (съеден 1 поврежденный байт).

```go
r, size, err := bb.ReadRune()
if err != nil {
    return err // Ошибка I/O (например, io.EOF)
}

if r == utf8.RuneError && size == 1 {
    // В потоке обнаружен поврежденный или оборванный байт UTF-8!
    return ErrCorruptedRune
}
```

## 5. Паттерн Sentinel Errors (Ошибки-маркеры) в бинарных протоколах

В сетевых модулях и парсерах крайне важно точно сообщать вызывающему коду причину сбоя:

```go
var (
    ErrInvalidSignature = errors.New("invalid frame signature: expected 0xAA")
    ErrMalformedFrame   = errors.New("malformed frame: corrupted payload or delimiter")
    ErrCorruptedRune    = errors.New("corrupted utf-8 rune in stream")
)
```

### Почему нельзя возвращать одну общую ошибку на всё?
* Если не совпала сигнатура `0xAA` — это чужой пакет (пакет другого протокола).
* Если сигнатура верна, но нет разделителя `':'` или конечного байта `0xFF` — это пакет нашего протокола, но поврежденный в сети (Drop / Resend).
* Если в теле битый байт UTF-8 — проблема на стороне передающего датчика.

Проверка через `errors.Is`:
```go
if errors.Is(err, ErrInvalidSignature) {
    // Игнорируем чужой мусор
} else if errors.Is(err, ErrMalformedFrame) {
    // Запрашиваем повторную отправку кадра
} else if errors.Is(err, ErrCorruptedRune) {
    // Логируем сбой датчика
}
```

## 6. Идиоматичный шаблон сетевого фрейма (IoT / Protocol Framer)

### Сериализация (Сборка кадра):
```go
func FrameBuilder(id byte, text string, r rune) []byte {
    var b bytes.Buffer
    b.WriteByte(0xAA)   // Magic byte начала фрейма
    b.WriteByte(id)     // Идентификатор устройства (1 байт)
    b.WriteByte(':')    // Текстовый разделитель
    b.WriteString(text) // Полезная нагрузка (ASCII)
    b.WriteByte(0x00)   // NULL-терминатор конца строки
    b.WriteRune(r)      // Unicode-статус (автоматически 1..4 байта UTF-8)
    b.WriteByte(0xFF)   // Маркер конца кадра (End of Frame)
    return b.Bytes()
}
```

### Десериализация (Разбор кадра):
```go
func StreamInspector(b []byte) error {
    if len(b) == 0 {
        return ErrMalformedFrame
    }

    bb := bytes.NewBuffer(b)

    // 1. Проверка сигнатуры
    if sig, err := bb.ReadByte(); err != nil || sig != 0xAA {
        return ErrInvalidSignature
    }

    // 2. Чтение ID устройства
    id, err := bb.ReadByte()
    if err != nil {
        return ErrMalformedFrame
    }
    _ = id

    // 3. Проверка разделителя
    if del, err := bb.ReadByte(); err != nil || del != ':' {
        return ErrMalformedFrame
    }

    // 4. Чтение строки до NULL-терминатора
    nameBytes, err := bb.ReadBytes(0x00)
    if err != nil {
        return ErrMalformedFrame
    }
    _ = nameBytes

    // 5. Чтение Unicode статуса
    r, size, err := bb.ReadRune()
    if err != nil {
        return ErrMalformedFrame
    }
    if r == utf8.RuneError && size == 1 {
        return ErrCorruptedRune
    }

    // 6. Проверка конца кадра
    if end, err := bb.ReadByte(); err != nil || end != 0xFF {
        return ErrMalformedFrame
    }

    return nil
}
```

## 7. Вопросы для технических собеседований (FAQ)

### Вопрос 1: В чем разница между `byte` и `uint8`?
**Ответ:** Разницы нет вообще. `byte` — это явный alias для `uint8`. В коде они полностью взаимозаменяемы. Название `byte` используется для подчеркивания семантики работы с сырыми данными или кодировками.

### Вопрос 2: Что произойдет, если передать в `bytes.Buffer.WriteByte` число больше 255?
**Ответ:** Код не скомпилируется, так как сигнатура метода требует тип `byte` (`uint8`). Если выполнить явное приведение `buf.WriteByte(byte(256))`, произойдет переполнение и будет записан младший байт: `256 % 256 = 0`.

### Вопрос 3: Как `bytes.Buffer.ReadRune()` сигнализирует о невалидном UTF-8?
**Ответ:** Метод `ReadRune()` не возвращает ошибку через параметр `error` при нарушении кодировки. Он возвращает символ `utf8.RuneError` (`0xFFFD` / `65533`) и размер `size = 1`. Ошибка `err` возвращается только при проблемах ввода-вывода (например, `io.EOF`).

### Вопрос 4: Как создать `bytes.Buffer` из уже существующего среза `[]byte` без аллокаций?
**Ответ:** Через функцию `bytes.NewBuffer(slice)`. Она создает структуру буфера, поле `buf` которой ссылается на существующий массив в памяти, в отличие от создания пустого буфера и вызова `WriteString`, который копирует память.
