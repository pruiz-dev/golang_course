# База Знаний: Анатомия строк в Go — Байты, Руны и Механика UTF-8

## 1. Внутреннее устройство строки: `StringHeader`

В Go строка (`string`) — это **иммутабельная (доступная только для чтения) последовательность байтов**.
На уровне рантайма (в оперативной памяти) переменная типа `string` занимает ровно **16 байт** (на 64-битной архитектуре) и представляет собой двухсловную структуру:

```go
type StringHeader struct {
    Data uintptr // 8 байт: прямой указатель на непрерывный массив байтов в памяти
    Len  int     // 8 байт: количество физических БАЙТОВ в строке
}
```

```
Переменная s (16 байт на стеке)
┌─────────────────────────┬─────────────────────────┐
│ Data: 0x1040a000 (8 байт)│ Len: 21 (8 байт)        │
└────────────┬────────────┴─────────────────────────┘
             │
             ▼
Физический массив байтов в памяти (Куча или Read-Only сегмент):
[ 0x47, 0x6f, 0x3a, 0x20, 0xd0, 0x9f, 0xd1, 0x80, ... ]
```

### Ключевые архитектурные свойства строки:
1. **Отсутствие поля `Cap` (Capacity):** В отличие от среза (`SliceHeader`), у строки нет ёмкости. Строка неизменяема, её нельзя расширить на месте через `append` без создания нового объекта в памяти.
2. **Иммутабельность данных:** Память, на которую указывает `Data`, защищена от прямой модификации. Попытка изменить байт через `s[0] = 'a'` пресекается компилятором еще на этапе сборки: `cannot assign to s[0]`.
3. **Бесплатное копирование:** При передаче строки в функцию копируются только 16 байт заголовка (`StringHeader`). Сами символы в памяти **не дублируются**.

## 2. Почему не выделить по 4 байта на каждый символ? (UTF-32 vs UTF-8)

Логичный вопрос разработчика: *«Раз максимальный символ Unicode укладывается в 4 байта, почему бы просто не выделить фиксированно по 4 байта на каждый символ строки?»*

Именно так устроен формат **UTF-32** (и тип `[]rune` в Go). Но для хранения строк во всем мире и в Go выбран формат **UTF-8**.

### Проблема UTF-32 (Раздувание памяти в 4 раза)
Большая часть текстов в интернете, исходного кода, конфигураций, форматов JSON и HTML состоит из символов латиницы, цифр и управляющих знаков (ASCII).
Код буквы `'A'` в Unicode равен `65` (`0x41`).

* **В UTF-32 (фиксированные 4 байта на символ):**
  Буква `'A'` хранится как: `0x41 0x00 0x00 0x00`.
  Три байта из четырех — **это бесполезные нули**.
  JSON-ответ размером 1 МБ в UTF-32 весил бы **4 МБ**. Это раздуло бы трафик интернета, оперативную память серверов и кэши процессоров в 4 раза!

* **В UTF-8 (переменная длина 1–4 байта):**
  Кодировка UTF-8 была разработана в 1992 году Кеном Томпсоном и Робом Пайком (авторами Unix и Go).
  Она пакует символы **максимально плотно**:
  * Английские буквы и цифры занимают ровно **1 байт** (100% обратная совместимость с ASCII).
  * Кириллица, греческий, арабский — **2 байта**.
  * Китайские, японские иероглифы — **3 байта**.
  * Эмодзи и редкие математические символы — **4 байта**.

## 3. Физическая раскладка байтов в памяти

В строке Go байты уложены плотно друг за другом, без разделителей и пустых ячеек.

Рассмотрим строку: `"Go: Привет 🚀"`

```
Физическая память (RAM):
Индекс:    0      1      2      3       4      5       6      7     ...    17     18     19     20
Байт:    | 0x47 | 0x6F | 0x3A | 0x20 || 0xD0 | 0x9F || 0xD1 | 0x80 | ... || 0xF0 | 0x9F | 0x9A | 0x80 |
Символ:  | 'G'  | 'o'  | ':'  | ' '  ||     'П'     ||     'р'     | ... ||          '🚀'           |
Размер:  | 1 б  | 1 б  | 1 б  | 1 б  ||   2 байта   ||   2 байта   | ... ||        4 байта         |
```

* Количество видимых символов (рун): **12**.
* Физический размер в байтах: **21 байт**.
* Встроенная функция `len(s)` возвращает **21** (длину физического массива байт, `Len` из `StringHeader`).

## 4. Как компьютер понимает границы символов переменной длины?

Если байты лежат подряд, как рантайм Go определяет, где заканчивается один символ и начинается другой?
Длина каждого символа закодирована **в префиксных битах первого байта**:

| Длина символа | 1-й байт (битовая маска) | Байты продолжения | Описание правила |
| :--- | :--- | :--- | :--- |
| **1 байт (ASCII)** | `0xxxxxxx` | *(нет)* | Старший бит равен `0`. Символ занимает ровно 1 байт. |
| **2 байта (Кириллица)**| `110xxxxx` | `10xxxxxx` | Начинается с двух единиц `110...`. Символ занимает 2 байта. |
| **3 байта (Иероглифы)**| `1110xxxx` | `10xxxxxx` `10xxxxxx` | Начинается с трех единиц `1110...`. Символ занимает 3 байта. |
| **4 байта (Эмодзи)**   | `11110xxx` | `10xxxxxx` (3 раза) | Начинается с четырех единиц `11110...`. Символ занимает 4 байта. |

### Самосинхронизация UTF-8
Все вспомогательные байты продолжения внутри символа **всегда начинаются с битов `10...`**.  
Ни один первый байт символа не может начинаться с `10`.  
Благодаря этому рантайм Go или декодер, начав чтение с любого случайного байта в памяти, мгновенно определяет: находится он в начале символа или в середине чужого хвоста.

## 5. Ловушка побайтовой индексации: `s[i]`

Выражение `s[i]` возвращает значение типа **`byte`** (псевдоним для **`uint8`**), то есть ровно 1 сырой байт:

```go
s := "Go: Привет 🚀"

// Латинская буква 'G' (1 байт)
fmt.Println(s[0])         // 71 (код ASCII)
fmt.Println(string(s[0])) // "G" (работает, так как 1 байт = 1 символ)

// Русская буква 'П' (байты с индексами 4 и 5: 0xD0 и 0x9F)
fmt.Println(s[4])         // 208 (0xD0)
fmt.Println(string(s[4])) // "Ð" (КРАКОЗЯБРА!)
```

### Почему появился символ `Ð`?
Байт `s[4]` имеет значение `0xD0` (в двоичном виде `11010000`).  
Префикс `110...` сообщает декодеру: *«Я начало двухбайтового символа, за мной должен идти байт `10xxxxxx`»*.  
Вызов `string(s[4])` передал только один разорванный байт. Go обнаруживает невалидный UTF-8 и выводит символ ошибки декодирования / сырой байт ISO-8859-1 (`Ð`).

## 6. Что такое `rune` и когда её применять?

* **`rune`** — это встроенный псевдоним (type alias) для типа **`int32`** (4 байта).
* Руна представляет собой **одну неделимую кодовую точку Unicode (Code Point)**.
* 4 байта (32 бита) полностью покрывают все существующие символы человечества.

### Разница между `string` и `[]rune`:
* **`string`** — данные упакованы в UTF-8 (1-4 байта на символ). Экономит оперативную память и сетевой трафик. Индексация `s[i]` возвращает байты.
* **`[]rune`** — данные распакованы в UTF-32 (ровно 4 байта на символ). Доступ по индексу `runes[i]` возвращает полноценный символ за O(1), но требует в 2-4 раза больше памяти.

## 7. Способы обхода и анализа строк в Go

### 1. Подсчет реального числа символов
Встроенный `len(s)` считает байты. Для подсчета рун используется пакет `"unicode/utf8"`:
```go
import "unicode/utf8"

text := "Привет"
fmt.Println(len(text))                      // 12 байт
fmt.Println(utf8.RuneCountInString(text))  // 6 рун
```

### 2. Определение размера конкретной руны в UTF-8
```go
r := 'П'
size := utf8.RuneLen(r) // вернет 2
```

### 3. Цикл `for range` (Встроенный декодер UTF-8)
Компилятор Go встраивает в цикл `range` по строке автоматическое декодирование UTF-8:
```go
text := "Go: П"
for idx, r := range text {
    fmt.Printf("Байтовое смещение: %d, Руна: %c\n", idx, r)
}
```
Вывод:
```
Байтовое смещение: 0, Руна: G
Байтовое смещение: 1, Руна: o
Байтовое смещение: 2, Руна: :
Байтовое смещение: 3, Руна:  
Байтовое смещение: 4, Руна: П  <-- Смещение следующей руны перескочило бы на 6!
```
> ⚠️ **Важно:** Переменная `idx` в цикле `range` — это **байтовое смещение начала руны**, а не порядковый номер 0, 1, 2, 3...

## 8. Идиоматичный шаблон: Безопасное извлечение N-го символа

### Антипаттерн (Лишняя аллокация памяти):
```go
func getSymbolBad(s string, i int) string {
    runes := []rune(s) // АЛЛОКАЦИЯ В КУЧЕ! Создает новый срез на 4 * len(runes) байт
    return string(runes[i])
}
```

### Паттерн Middle-разработчика (Single-Pass, Zero-Allocations, Comma-OK):
```go
func getStrSymbolByIndex(s string, i int) (string, bool) {
    if i < 0 {
        return "", false
    }

    counter := -1
    for _, r := range s { // Декодирование на лету, 0 аллокаций
        counter++
        if counter == i {
            return string(r), true // Досрочный выход O(k)
        }
    }

    return "", false // Индекс вышел за пределы длины строки
}
```

## 9. Эталонный код практики 01 (`main.go`)

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "Go: Привет 🚀"

	strDiagnostics(s)
	strRange(s)

	if ch, ok := getStrSymbolByIndex(s, 5); ok {
		fmt.Printf("5-й символ: %s\n", ch)
	} else {
		fmt.Println("Индекс за пределами строки!")
	}
}

// getStrSymbolByIndex безопасно извлекает символ по порядковому номеру
// за один проход (Single-Pass) без аллокаций срезов в памяти.
func getStrSymbolByIndex(s string, i int) (string, bool) {
	if i < 0 {
		return "", false
	}

	counter := -1
	for _, r := range s {
		counter++
		if counter == i {
			return string(r), true
		}
	}

	return "", false
}

// strRange демонстрирует посимвольный обход UTF-8 строки через range.
func strRange(s string) {
	for idx, r := range s {
		fmt.Printf(
			"Symbol offset in bytes: %d\n"+
				"Bytes size is: %d\n"+
				"Rune: %c (code: %U)\n\n",
			idx, utf8.RuneLen(r), r, r,
		)
	}
}

// strDiagnostics демонстрирует разницу между байтами и рунами.
func strDiagnostics(s string) {
	bytesCount := len(s)
	symbolsCount := utf8.RuneCountInString(s)

	fmt.Printf(
		"Bytes count in str: %d\n"+
			"Symbols count in str: %d\n\n",
		bytesCount, symbolsCount,
	)

	firstByte := s[0]

	fmt.Printf(
		"first byte is: %v\n"+
			"type of firstByte is: %T\n\n",
		firstByte, firstByte,
	)

	// Демонстрация ловушки: взятие одного байта от 2-байтовой русской буквы 'П'
	// Индекс 4 в строке "Go: Привет 🚀" соответствует первому байту (0xD0) буквы 'П'
	fmt.Println("Попытка вывести одиночный байт буквы 'П':", string(s[4]))
}
```

## 10. Сводная шпаргалка к собеседованиям

1. **Что такое `string` в Go?**  
   Структура `StringHeader` (16 байт): указатель `Data` и длина `Len` в байтах. Данные иммутабельны.
2. **Что возвращает `len(s)`?**  
   Количество байт, а не символов.
3. **Как посчитать реальное количество символов?**  
   Через `utf8.RuneCountInString(s)`.
4. **Что возвращает `s[i]`?**  
   Тип `byte` (`uint8`) — 1 физический байт.
5. **Что такое `rune`?**  
   Псевдоним для `int32`, представляющий одну кодовую точку Unicode (UTF-32).
6. **Почему UTF-8, а не UTF-32?**  
   Экономия памяти до 4 раз, отсутствие пустых нулевых байтов для ASCII, обратная совместимость.
7. **Что возвращает `range` по строке?**  
   Пару `(байтовое_смещение int, руна rune)`.
