# База Знаний: Ловушка nil и Паника (Panic)

## 1. Что такое nil?
Если переменная-указатель создана, но в неё не записан никакой адрес, она получает "нулевое значение" (zero value) для указателей — **`nil`**.
`nil` означает "пустота" (физически это адрес `0x00000000`).

## 2. Ловушка `nil` и Panic
**Главное правило безопасности памяти:**
> Если ты разыменуешь `nil`-указатель (попытаешься сделать `*p = 10`, когда `p == nil`), операционная система запретит запись в нулевой адрес, и Go экстренно завершит программу (произойдет **panic**).
Ошибка будет выглядеть так: `panic: runtime error: invalid memory address or nil pointer dereference`.

### Анатомия паники: Правило двух ячеек
Часто возникает вопрос: *"У указателя `v` ведь есть ячейка памяти на стеке, внутри которой лежит `nil`. Почему нельзя просто переписать значение в ней через `*v = 10`?"*

Важно понимать, что при работе с указателями есть **ДВЕ разные ячейки памяти**:
1. **Собственная ячейка указателя (например, по адресу `0xAAA`).** В ней хранится адрес назначения. Если указатель пуст, в ней лежит `0x00000000`. Когда ты делаешь `v = new(int)`, ты записываешь новый адрес именно сюда. Это **безопасно**.
2. **Целевая ячейка (Разыменование `*`).** Когда ты делаешь `*v = 10`, процессор выполняет команду "Путешествие": он берет адрес из `0xAAA` (наш `nil` / `0x0`) и пытается пойти по нему, чтобы записать данные. Но адрес `0x0` жестко зарезервирован операционной системой как "запретная зона". Происходит немедленный Segmentation Fault (Паника).

## 3. Хитрая задача на собеседованиях (Quiz)
Рассмотрим пример:
```go
func modify(p *int) {
    if p == nil {
        p = new(int)
    }
    *p = 10
}

func main() {
    var v *int
    modify(v)
    if v == nil {
        fmt.Println("nil")
    } else {
        fmt.Println(*v)
    }
}
```
**Что выведет этот код?** Он выведет `nil` (без паники).

**Разбор:**
1. **Можно ли передавать `nil` в функцию?** Да. `nil` — это просто значение (`0x0`). В функцию передается **копия** этого пустого адреса.
2. Внутри `modify` проверяется условие `p == nil`, и создается новая память: `p = new(int)`. Это спасает от паники на строке `*p = 10`.
3. **Главный подвох:** Переменная `p` в `modify` — это **локальная копия** указателя. Назначая `p = new(int)`, мы меняем адрес только в локальной копии (зачеркиваем адрес на своей копии листка бумаги). Оригинальный указатель `v` в `main` как был `nil`, так `nil` и остался!

## 4. Как писать безопасный (Safe) код?
Никогда не доверяй указателям, приходящим в твою функцию извне (например, из базы данных). Всегда делай **Early Return (Ранний возврат)**.

```go
func Deposit(balance *int, amount int) {
    if balance == nil { // Safety Check
        fmt.Println("Ошибка: счет не найден!")
        return // Early return спасает от паники ниже!
    }
    *balance += amount // Сюда код дойдет, только если указатель валиден
}
```

### Инициализация через `new`
Если тебе нужно создать указатель "с нуля" внутри функции и сразу выделить под него безопасную память:
```go
safePtr := new(int) // Выделена память, внутри лежит 0, safePtr НЕ равен nil
*safePtr = 50       // Безопасно!
```
