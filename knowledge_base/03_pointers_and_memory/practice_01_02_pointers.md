# База Знаний: Указатели, Механика памяти и Безопасность (nil)

Этот документ объединяет знания из первых двух практик Модуля 03, посвященных основам работы с оперативной памятью в Go.

## 1. Значение vs Указатель
В Go **все параметры функций передаются по значению (копируются)**.
Когда переменная передается в функцию, создается её полный клон. Любые изменения внутри функции затрагивают только клон, а оригинал остается нетронутым.
Это отлично работает для маленьких данных, но создает две проблемы:
1. Мы не можем обновить оригинальные данные (например, счет в банке).
2. Копирование больших структур (например, на мегабайт) при каждом вызове функции убьет производительность.

Решение: **Указатели (Pointers)**.

## 2. Что такое указатель?
Указатель — это переменная, которая хранит не само значение (как число `42`), а **адрес в оперативной памяти**, по которому это значение лежит (например, `0xc00001a0a8`).

### Операторы работы с указателями:
* **`&` (Взятие адреса):** Возвращает физический адрес переменной. 
  *Пример:* `ptr := &hp` (мы получили адрес переменной `hp`).
  *Вывод адреса:* Для вывода адреса в консоль используется плейсхолдер `%p` в `fmt.Printf("%p", &hp)`.
* **`*` (Разыменование / Dereferencing):**
  * В декларации типа: `var p *int` (Означает "это указатель на целое число").
  * При работе с данными: `*p = 50` (Означает "пойди по адресу, который лежит в `p`, и запиши туда `50`").

### Идиоматичный код (Code Review Insight)
Инверсия булевых значений через указатель не требует громоздких `if/else`.
*Правильно и лаконично:*
```go
func ToggleCombat(inCombatPtr *bool) {
    *inCombatPtr = !*inCombatPtr // Читает старое значение по адресу, инвертирует и пишет обратно
}
```

## 3. Ловушка `nil` и Panic
Если переменная-указатель создана, но в неё не записан никакой адрес, она получает "нулевое значение" (zero value) для указателей — **`nil`**.
`nil` означает "пустота". 

**Главное правило безопасности памяти:**
> Если ты разыменуешь `nil`-указатель (попытаешься сделать `*p = 10`, когда `p == nil`), операционная система запретит запись в нулевой адрес, и Go экстренно завершит программу (произойдет **panic**).
Ошибка будет выглядеть так: `panic: runtime error: invalid memory address or nil pointer dereference`.

### Как писать безопасный (Safe) код?
Никогда не доверяй указателям, приходящим в твою функцию извне (например, из базы данных). Всегда делай **Early Return (Ранний возврат)**.

```go
func Deposit(balance *int, amount int) {
    if balance == nil { // Safety Check
        fmt.Println("Ошибка: счет не найден!")
        return // Early return спасает от паники ниже!
    }
    *balance += amount // Сюда код дойдет, только если указатель валиден
}
```

### Альтернатива: Инициализация через `new`
Если тебе нужно создать указатель "с нуля" внутри функции и сразу выделить под него безопасную память, используй встроенную функцию `new(Type)`.
```go
var p *int // p равен nil
safePtr := new(int) // Выделена память, внутри лежит 0, safePtr НЕ равен nil
*safePtr = 50 // Безопасно!
```

## 4. Изменение значения vs Изменение адреса (Магия Swap)
Частая ошибка новичков — путать перезапись данных по указателю с перезаписью самого указателя.
Представь, что указатель — это листок бумаги с написанным на нем адресом ("ул. Пушкина, 5"). Значение — это люди в доме.

Поскольку Go **копирует параметры**, функция получает **копию** твоего листка бумаги с тем же адресом.

### Ошибка: `p = &b` (Изменение адреса)
Если внутри функции ты зачеркнешь адрес на своем листке и напишешь новый (`a = b`), ты поменяешь адрес только на своей копии листка. Оригинальный листок в функции `main` останется прежним. Реальные данные не изменятся.
```go
// Так нельзя поменять переменные местами (Failed Swap)
func FailedSwap(a *int, b *int) {
    a, b = b, a // Меняются только локальные бумажки-копии
}
```

### Правильно: `*p = 5` (Изменение значения)
Если ты используешь разыменование `*`, ты говоришь: *"Пойди по адресу с листка и поменяй жильцов"*. Это повлияет на оригинальные данные.
```go
// Так правильно! (Success Swap)
func SuccessSwap(a *int, b *int) {
    *a, *b = *b, *a // Мы пошли по адресам и поменяли местами реальные данные
}
```

> **Code Review Insight:** Обрати внимание на синтаксис `*a, *b = *b, *a`. Это **множественное присваивание** — мощная идиоматичная фишка Go. Она позволяет менять переменные местами атомарно, без создания третьей временной переменной (temp/c). Все значения справа вычисляются до начала присваивания налево.
