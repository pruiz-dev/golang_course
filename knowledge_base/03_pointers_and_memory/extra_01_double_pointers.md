# База Знаний: Двойная косвенность (Указатель на указатель)

Этот файл покрывает продвинутую тему, когда нам нужно из функции изменить не *данные* по указателю, а **сам адрес**, лежащий внутри оригинальной переменной-указателя.

## 1. Суть проблемы
Представь, что в `main` у тебя есть указатели `ptrX` и `ptrY`. Ты передаешь их в функцию `Swap(a, b *int)`.
По правилам Go, параметры функции **копируются**. Значит, внутри `Swap` переменные `a` и `b` — это лишь **копии** твоих оригинальных указателей.
Если ты напишешь `a, b = b, a`, ты поменяешь местами только локальные копии. Оригинальные `ptrX` и `ptrY` в функции `main` останутся нетронутыми!

## 2. Указатель на указатель (`**int`)
Чтобы функция могла изменить *адрес*, лежащий внутри `ptrX`, мы должны передать ей **адрес самого `ptrX`** (адрес указателя).
Его тип будет `**int` (указатель на указатель).

```go
func HardcoreSwap(a, b **int) {
    // Разыменовываем один раз (*a), чтобы добраться до оригинальной "коробочки" ptrX.
    // Кладем в нее то, что лежит в "коробочке" ptrY (*b).
    *a, *b = *b, *a
}

func main() {
    x, y := 10, 20
    ptrX, ptrY := &x, &y // ptrX имеет тип *int
    
    // Передаем адреса самих указателей! (&ptrX имеет тип **int)
    HardcoreSwap(&ptrX, &ptrY)
    
    // Теперь ptrX указывает на y, а ptrY указывает на x!
}
```

## 3. Анатомия в памяти (Разбор)
Визуально это работает так:
1. Переменная `a` хранит адрес переменной `ptrX` (например, `&ptrX`).
2. Когда мы пишем `*a`, мы "идем" по этому адресу и физически обращаемся к оригинальной переменной `ptrX`.
3. Мы берем то, что лежит в `*b` (оригинальный `ptrY`), и записываем это в `ptrX`.

**Итог:** Сами переменные `x` и `y` (со значениями 10 и 20) вообще не трогались. Мы перекинули "ниточки", которыми указатели `ptrX` и `ptrY` были привязаны к `x` и `y`.

## 4. Где это применяется?
В бизнес-логике Go двойные указатели (`**Type`) встречаются **очень редко**. Считается плохим тоном заставлять функцию менять переданный указатель; гораздо идиоматичнее просто вернуть новый указатель:
```go
// Хороший стиль:
func NewConfig() *Config {
    return &Config{}
}
```
Однако двойная косвенность активно используется "под капотом" в пакетах типа `encoding/json` (когда парсер сам выделяет память под структуру и меняет переданный ему указатель), а также при низкоуровневой работе со связными списками и графами.
