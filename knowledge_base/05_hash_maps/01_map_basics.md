# База Знаний: Основы работы с Хэш-таблицами (Maps)

Мапа (`map`) в Go — это мощная встроенная структура данных для хранения пар "ключ-значение". Поиск, добавление и удаление элементов происходят в среднем за время $O(1)$.

## 1. Объявление и Создание (Nil Map vs Initialized Map)

Главное правило: **Запись в неинициализированную (nil) мапу вызывает панику.**

```go
// 1. Неинициализированная мапа (Zero Value = nil)
var nilMap map[string]int
// nilMap["Alice"] = 25 // ПАНИКА! panic: assignment to entry in nil map

// 2. Инициализация через make (Идиоматично для пустых мап)
goodMap := make(map[string]int)
goodMap["Alice"] = 25 // Работает отлично

// 3. Литерал (Идиоматично, если сразу знаешь стартовые данные)
ages := map[string]int{
    "Alice": 25,
    "Bob":   30, // Обязательная запятая
}
// Пустой литерал (эквивалент make)
emptyMap := map[string]int{} 
```

## 2. Добавление и Обновление (CRUD)
Если ключа нет — он создастся. Если ключ есть — значение перезапишется.
```go
inventory := make(map[string]int)
inventory["Gold"] = 100 // Создание
inventory["Gold"] = 200 // Обновление
```

## 3. Чтение и Zero Values
Если ты запросишь несуществующий ключ, Go **не выбросит ошибку**. Он вернет "Нулевое Значение" (Zero Value) для типа значения.

```go
stats := map[string]int{"Strength": 10}

// Ключа "Agility" нет, но переменная получит дефолтный ноль (0 для int)
agi := stats["Agility"] 
fmt.Println(agi) // Выведет 0
```

## 4. Проверка наличия (Идиома Comma Ok)
Из-за свойства возвращать Zero Value возникает логическая проблема:
Как понять, у игрока действительно `0` золота, или ключа "Gold" вообще нет в мапе?
Для этого используется двойное присваивание.

```go
val, ok := stats["Agility"]

if ok {
    fmt.Println("Значение существует:", val)
} else {
    fmt.Println("Такого ключа нет в базе!")
}

// Компактный синтаксис (часто используется в Go):
if val, ok := stats["Agility"]; ok {
    // Входим сюда только если ключ найден
    fmt.Println(val)
}
```

## 5. Удаление элементов (`delete`)
Функция `delete` удаляет ключ из мапы. Если ключа там и так не было, функция просто проигнорирует команду (никаких паник не будет).
```go
delete(stats, "Agility") 
delete(stats, "UnknownKey") // Ничего не произойдет, это безопасно
```

## 6. Передача в функции: Map vs Slice (Под капотом)
Это один из самых частых вопросов на собеседованиях. Давай сравним, что физически лежит в переменных слайса и мапы.

### Слайс: Переменная — это Структура (24 байта)
Переменная-слайс — это структура `SliceHeader`. У неё есть свои поля: указатель `Data`, `Len` и `Cap`.
Когда ты передаешь слайс в функцию, копируется **вся 24-байтовая структура**.
Если внутри функции `append` решит выделить новую память (переаллокация), он обновит указатель `Data` в **локальной копии** структуры. Оригинальная структура в `main` так и останется смотреть на старый массив.
*Именно поэтому после `append` мы обязаны возвращать измененный слайс обратно: `s = append(s, val)`.*

### Мапа: Переменная — это Указатель (8 байт)
Переменная-мапа — это **НЕ** структура. Это **чистый указатель** (pointer), занимающий ровно 8 байт на Стеке. Этот указатель смотрит на большую сложную структуру `hmap`, которая всегда лежит в Куче (Heap).
Когда ты передаешь мапу в функцию, копируется только этот 8-байтовый указатель. 
Теперь у нас есть два указателя (в `main` и в функции), но оба они смотрят **на одну и ту же структуру `hmap`** в Куче.

```go
func modifyMap(m map[string]int) {
    // Пишем данные. Если мапе нужно будет вырасти, она обновит 
    // внутренние бакеты внутри структуры hmap в Куче.
    m["Hacked"] = 999 
}

func main() {
    m := make(map[string]int)
    modifyMap(m) // Передали 8-байтовый указатель
    
    // Структура hmap в Куче изменилась, а наш указатель m 
    // всё так же смотрит на неё. Мы сразу видим изменения!
    fmt.Println(m["Hacked"]) // Выведет 999
}
```

**Вывод:** Поскольку переменная-мапа — это просто указатель на единый центр управления (`hmap`), тебе **никогда не нужно** возвращать мапу из функции при добавлении/удалении элементов (в отличие от слайсов с их `append`). Все функции работают с одной и той же структурой `hmap` в памяти.
