# Практика 01: Реестр Облачной Инфраструктуры (Cloud Resource Registry)

## Контекст задачи
В облачных платформах (AWS, GCP, Yandex Cloud) учет вычислительных ресурсов строится на композиции сущностей. Любой ресурс (виртуальная машина, сетевой диск, балансировщик нагрузки) обладает общими метаданными (UUID, имя, регион, временные метки, статус жизненного цикла), но расширяется специфическими техническими параметрами.

Попытка моделировать такие системы без понимания композиции приводит либо к дублированию полей в десятках структур, либо к нарушению инкапсуляции, когда внешний код напрямую меняет критические системные поля в обход валидации.

Ваша задача — спроектировать ядро каталога ресурсов с четким разделением на пакеты, встраиванием структур и защитой инвариантов бизнес-логики.

---

## Техническое задание (Requirements)

### 1. Архитектурная структура и пакетное разделение
* Программа должна состоять как минимум из двух пакетов:
  * Исполняемый пакет `main` (точка входа, оркестрация, демонстрация и вывод).
  * Внутренний доменный пакет (например, `registry` или `model`), содержащий структуры данных, конструкторы и бизнес-правила.
* Проект должен представлять собой самостоятельный Go-модуль.

### 2. Моделирование предметной области (Композиция)
* Спроектируйте базовую сущность метаданных ресурса (`ResourceMetadata` или `BaseResource`):
  * Общедоступные поля: уникальный идентификатор (ID), наименование (Name), регион размещения (Region), время создания (CreatedAt).
  * **Инкапсулированное (неэкспортированное) поле:** внутреннее состояние/статус ресурса (например, `status string` со значениями вроде `"PROVISIONING"`, `"RUNNING"`, `"STOPPED"`). Это поле не должно изменяться из внешних пакетов напрямую!
  * Предоставьте метод-геттер для чтения статуса, а также метод для контролируемого переключения жизненного цикла (например, перевод в статус `"RUNNING"` или `"TERMINATED"` с валидацией перехода).
* Спроектируйте специфические инфраструктурные ресурсы с помощью **встраивания по значению**:
  * **Виртуальная машина (Compute Node):** встраивает базовые метаданные, содержит количество CPU ядер (int), объем оперативной памяти в ГБ (int), флаг наличия GPU (bool).
  * **Сетевой том (Storage Volume):** встраивает базовые метаданные, содержит объем диска в ГБ (int), тип носителя (например, `"SSD"`, `"HDD"`).

### 3. Защита инвариантов (Конструкторы)
* Запретите создание некорректных структур из внешних пакетов за счет неэкспортированных полей и предоставьте безопасные фабричные функции-конструкторы:
  * `NewComputeNode(...) (*ComputeNode, error)`
  * `NewStorageVolume(...) (*StorageVolume, error)`
* Валидация должна отсекать недопустимые значения:
  * Пустые идентификаторы, имена и регионы.
  * Неположительное количество ядер (CPU <= 0), RAM (RAM <= 0) или объема диска (SizeGb <= 0).
  * Недопустимый тип диска (только `"SSD"` или `"HDD"`).
* При нарушении любого условия функция возвращает понятную ошибку `error`.

### 4. Агрегация и Анонимные структуры
* Реализуйте функционал реестра или агрегатора, принимающего список созданных ресурсов.
* Для формирования итоговой сводки инфраструктуры (Total CPU, Total RAM, Total Storage, количество активных ресурсов по типам) используйте **анонимную структуру** прямо в месте вычисления/вывода, не создавая под этот разовый отчет лишний глобальный тип.

---

## Критерии приемки (Acceptance Criteria)

1. Проект инициализирован как отдельный Go-модуль с файлом `go.mod`.
2. Код организован в нескольких файлах и разделен минимум на два пакета (`main` и доменный пакет).
3. Инкапсуляция соблюдена: поле статуса ресурса невозможно изменить напрямую из пакета `main` в обход методов валидации.
4. Использовано встраивание структур (composition embedding). В коде `main` продемонстрирован доступ к полям базовых метаданных через «продвинутые» поля (promoted fields, например `node.Name`, `node.Region`).
5. Конструкторы возвращают ошибку при передаче некорректных аргументов (продемонстрируйте обработку хотя бы одного ошибочного случая создания).
6. Итоговый отчет агрегации формируется с помощью локальной анонимной структуры и аккуратно выводится в консоль.
7. Программа успешно компилируется и выполняется командой `$ go run .` (или `$ go run main.go`).

---

## Архитектурные подсказки (High-Level Hints)

* Создайте директорию пакета (например, `registry`) внутри каталога практики. В ней опишите базовые структуры и конструкторы.
* Внимательно следите за регистром первой буквы полей: если поле должно быть доступно из `main`, его имя должно начинаться с заглавной буквы. Поля, требующие сокрытия данных, должны начинаться со строчной буквы.
* Встраивание осуществляется простым указанием имени типа внутри структуры без имени поля:
  ```go
  type ComputeNode struct {
      ResourceMetadata
      Cores int
      // ...
  }
  ```
* Для инициализации встроенной структуры внутри конструктора используйте имя встроенного типа в качестве ключа литерала.
