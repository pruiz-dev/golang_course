# Теория: Анатомия структур в Go — Композиция, Встраивание и Инкапсуляция

## 1. Что такое структура в Go?

В Go нет классов, объектов и классического наследования. Основным инструментом моделирования предметной области и группировки разнородных данных является **структура (`struct`)**.

Физически структура представляет собой **последовательный непрерывный блок памяти**, в котором поля размещаются строго в порядке их объявления:

```go
type Node struct {
    ID    int64
    IP    string
    Cores int
}
```

### Ключевые свойства структур:
1. **Тип-значение (Value Type):** Структура в Go является типом-значением. При присваивании переменной структуры другой переменной или передаче в функцию по значению (`func inspect(n Node)`) происходит **полное побайтовое копирование** всех полей.
2. **Нулевое значение (Zero Value):** При объявлении структуры без явной инициализации (`var n Node`) все её поля гарантированно инициализируются своими нулевыми значениями (`0` для чисел, `""` для строк, `false` для булевых, `nil` для указателей, слайсов, мап и интерфейсов). В Go принято проектировать структуры так, чтобы их нулевое значение было сразу готово к безопасному использованию (например, `sync.Mutex` или `bytes.Buffer`).

## 2. Способы инициализации структур

Существует несколько способов создания и заполнения структур. На практике они обладают разной степенью надежности.

### 1. Литерал с именованными полями (Идиоматичный подход)
```go
node := Node{
    ID:    101,
    IP:    "192.168.1.10",
    Cores: 8,
}
```
* **Плюсы:** Читаемость, независимость от порядка объявления полей. При добавлении нового поля в структуру старый код не сломается — новое поле просто получит zero-value. Это стандарт для продакшен-кода.

### 2. Позиционный литерал (Антипаттерн)
```go
node := Node{101, "192.168.1.10", 8}
```
* **Минусы:** Хрупкий код. Если кто-то поменяет порядок полей или добавит новое поле в `Node`, такой код упадет с ошибкой компиляции. Использовать в продакшене строго не рекомендуется (допускается только в редких тривиальных тестах или примитивных типах вроде точки `Point{x, y}`).

### 3. Функции-конструкторы (`New...`)
Поскольку в Go нет встроенного ключевого слова `constructor`, используется паттерн фабричной функции:
```go
func NewNode(id int64, ip string, cores int) (*Node, error) {
    if cores <= 0 {
        return nil, errors.New("cores count must be positive")
    }
    return &Node{
        ID:    id,
        IP:    ip,
        Cores: cores,
    }, nil
}
```
Конструктор позволяет гарантировать валидность инвариантов бизнес-логики и скрыть внутренности структуры.

## 3. Встраивание структур (Struct Embedding)

В Go отсутствует ключевое слово `extends`. Вместо наследования ("является кем-то" / "is-a") Go придерживается философии **композиции** ("содержит в себе" / "has-a").

Для повторного использования полей и методов используется **встраивание структур (struct embedding)**: указание типа другой структуры внутри структуры без явного имени поля:

```go
type BaseResource struct {
    ID        string
    CreatedAt int64
}

type ComputeNode struct {
    BaseResource // Встроенная (анонимная) структура
    Cores        int
    RAMGb        int
}
```

### Продвижение полей (Promoted Fields)
Поля и методы встроенной структуры «продвигаются» на внешний уровень. К ним можно обращаться напрямую:

```go
vm := ComputeNode{
    BaseResource: BaseResource{
        ID:        "node-01",
        CreatedAt: 1700000000,
    },
    Cores: 16,
    RAMGb: 64,
}

// Прямой доступ через promoted field:
fmt.Println(vm.ID) // "node-01"

// Полный доступ через имя типа:
fmt.Println(vm.BaseResource.ID) // "node-01"
```

### Затенение полей (Field Shadowing)
Если у внешней структуры есть поле с точно таким же именем, как у встроенной, внешнее поле перекрывает (затеняет) внутреннее:

```go
type StorageNode struct {
    BaseResource
    ID int64 // Затеняет BaseResource.ID (string)!
}

disk := StorageNode{
    BaseResource: BaseResource{ID: "legacy-uuid-001"},
    ID:           42,
}

fmt.Println(disk.ID)                // 42 (поле верхнего уровня)
fmt.Println(disk.BaseResource.ID)   // "legacy-uuid-001" (явное обращение к вложенному)
```

### Коллизии имен при множественном встраивании (Ambiguous Selector)
Если в структуру встроены две структуры, содержащие одинаковые поля, прямое обращение вызовет ошибку компиляции:

```go
type NetworkInfo struct {
    Status string
}

type DiskInfo struct {
    Status string
}

type Server struct {
    NetworkInfo
    DiskInfo
}

srv := Server{}
// srv.Status -> Ошибка компиляции: ambiguous selector srv.Status!
// Компилятор не знает, чей Status имеется в виду.

// Решение — явная квалификация:
fmt.Println(srv.NetworkInfo.Status)
fmt.Println(srv.DiskInfo.Status)
```

## 4. Встраивание по значению vs по указателю

Структуру можно встроить как значение (`BaseResource`) или как указатель (`*BaseResource`):

```go
type Container struct {
    *BaseResource
    Image string
}
```

### Критическая опасность встраивания указателя:
Если встроенный указатель не был проинициализирован, он равен `nil`. Любая попытка обратиться к продвинутому полю приведет к панике времени выполнения (nil pointer dereference):

```go
c := Container{Image: "alpine:latest"}
fmt.Println(c.ID) // ПАНИКА! c.BaseResource == nil
```

> **Правило:** В 95% случаев встраивайте структуры **по значению** (`T`), чтобы гарантировать целостность памяти и отсутствие скрытых `nil`-разыменований. Встраивание по указателю (`*T`) оправдано только тогда, когда несколько внешних сущностей должны разделять одно и то же изменяемое состояние.

## 5. Пакетная инкапсуляция и сокрытие данных

В Go нет модификаторов `private`, `protected`, `public`. Доступность определяется исключительно регистром первой буквы имени:
* **С заглавной буквы (`Exported`):** Идентификатор экспортируется наружу пакета.
* **Со строчной буквы (`unexported`):** Идентификатор виден только внутри текущего пакета.

Это правило применяется и к именам самих структур, и к каждому полю внутри них:

```go
package wallet

type Account struct {
    Owner   string  // Экспортировано: любой внешний пакет может прочитать и изменить
    balance int64   // Неэкспортировано: доступно ТОЛЬКО внутри пакета wallet
}

// Конструктор обеспечивает инвариант
func NewAccount(owner string, initialBalance int64) (*Account, error) {
    if initialBalance < 0 {
        return nil, errors.New("initial balance cannot be negative")
    }
    return &Account{Owner: owner, balance: initialBalance}, nil
}

// Геттер для контролируемого доступа
func (a *Account) Balance() int64 {
    return a.balance
}
```

Если внешний пакет попытается создать `Account{Owner: "Bob", balance: 100}`, компилятор не разрешит обратиться к `balance`. Это фундаментальный механизм инкапсуляции в Go.

## 6. Анонимные структуры

Структура может быть объявлена локально без выделения отдельного именованного типа через `type`:

```go
config := struct {
    Host string
    Port int
}{
    Host: "127.0.0.1",
    Port: 8080,
}
```

### Где это идиоматично применять:
1. **Table-driven тесты:** Создание таблиц тест-кейсов (`tests := []struct{ name string; input int; want int }{ ... }`).
2. **Одноразовый парсинг JSON:** Когда API возвращает сложный JSON с десятком вложенных сущностей, но сервису нужны всего два поля, объявление анонимной структуры прямо внутри функции избавляет проект от мусорных глобальных типов.
