# Урок 9: Под капотом — Устройство Слайсов

Ты уже знаешь, что слайс — это динамический массив. Но чтобы успешно проходить собеседования и не ловить баги (утечки памяти, неожиданные изменения данных), нужно знать, как он устроен внутри.

### Структура Слайса (Slice Header)
Под капотом любой слайс в Go — это маленькая структура (struct) из трех полей:
1. **Pointer** — указатель на базовый массив (underlying array) в памяти, где реально лежат данные.
2. **Length (len)** — длина (сколько элементов сейчас доступно для чтения).
3. **Capacity (cap)** — вместимость (сколько всего элементов вмещает базовый массив до того, как его придется увеличивать).

### Магия `append` и Аллокации памяти
Когда ты делаешь `append`, Go проверяет:
- Если `len < cap`, то в базовом массиве еще есть свободное место. Go просто записывает туда новое значение и увеличивает `len` на 1.
- Если `len == cap`, место закончилось! Go делает следующее:
  1. Выделяет в памяти **новый** массив большего размера (обычно в 2 раза больше старого).
  2. Копирует все старые данные в новый массив.
  3. Записывает новый элемент.
  4. Меняет `Pointer` в заголовке слайса на новый массив. Старый массив удаляется сборщиком мусора.

Это называется **аллокация (allocation)**. Аллокации — это медленно. Поэтому, если ты заранее знаешь, сколько элементов будет в слайсе, лучше создавать его с нужным `cap` через функцию `make`, чтобы избежать лишних переаллокаций памяти.

```go
// Создаем пустой слайс (len=0), но заранее резервируем память на 10 элементов (cap=10)
nums := make([]int, 0, 10) 
```
