# Практика: Защита банковской транзакции

## Задача (Бизнес-требование)
Ты разрабатываешь ядро банковского приложения, отвечающее за пополнение баланса клиентов. Иногда из-за сбоев в базе данных вместо реального счета клиента в твою функцию приходит "пустота" (nil-указатель). 
Твоя задача — написать функцию пополнения, которая **никогда не падает**, даже если в нее передали "пустоту", а аккуратно обрабатывает эту ошибку.

## Критерии приемки (Acceptance Criteria)
1. Создай исполняемую программу (пакет `main`).
2. Напиши функцию `Deposit`, которая принимает **указатель** на баланс клиента (число) и сумму пополнения (amount).
3. Функция должна прибавить сумму к балансу.
4. **Критическое условие:** Функция не должна вызывать `panic`, если указатель на баланс отсутствует (равен `nil`). В этом случае функция должна просто вывести в консоль `Критическая ошибка: счет не найден!` и завершить работу.
5. В функции `main` ты должен смоделировать две ситуации:
   - **Успешный сценарий:** Создать реальную переменную баланса (например, 1000), передать ее адрес в `Deposit` (добавить 500) и вывести итоговый баланс (должно стать 1500).
   - **Сценарий сбоя:** Создать "пустой" указатель на `int` и передать его в `Deposit`. Программа должна вывести сообщение об ошибке, но **продолжить работу до конца**, не "упав" с паникой. Выведи в конце `Программа успешно завершена.`, чтобы доказать, что паники не было.

## Архитектурные подсказки
- Чтобы создать "пустой" указатель, достаточно объявить переменную без инициализации: `var missingAccount *int`. Либо при вызове функции можно передать ключевое слово `nil` напрямую.
- Для проверки на пустоту используй классический оператор сравнения `if ... == nil`.

Спроектируй код так, чтобы он был "пуленепробиваемым". Жду результат!
