# Теория: Опасность nil-указателей и Паники

Указатели — это мощный инструмент, но они приносят с собой одну из самых частых и опасных ошибок в программировании на Go.

## Что такое nil?
В Go любая переменная при создании получает "нулевое значение" (zero value) своего типа. 
- Для `int` это `0`.
- Для `bool` это `false`.
- Для указателей (а также слайсов, мап, каналов и интерфейсов) это `nil`.

`nil` означает **"пустота, отсутствие адреса"**. Указатель есть, но он никуда не указывает.

```go
var p *int // Создан указатель, но он равен nil
fmt.Println(p) // Выведет: <nil>
```

## Фатальная ошибка: Dereference of nil
Главное правило: **Разыменовывать (ставить звездочку `*` перед указателем) можно только тот указатель, который указывает на реальную память!**

Если ты попытаешься пойти по адресу `nil` и записать туда данные, программа немедленно "упадет" (сработает механизм `panic`).
```go
var p *int
*p = 10 // 💥 PANIC! runtime error: invalid memory address or nil pointer dereference
```
Go защищает оперативную память твоего компьютера. Запись в нулевой адрес неминуемо приведет к краху операционной системы, поэтому программа экстренно убивает сама себя.

## Как избежать паники?
У тебя есть два пути работы с указателями:

**1. Проверка на `nil` (Safety Check)**
Если указатель приходит в функцию извне, ты никогда не можешь быть уверен, что он валиден. Идиоматичный Go-код требует проверок:
```go
func update(p *int) {
    if p == nil {
        fmt.Println("Ошибка: указатель пуст!")
        return
    }
    *p = 10 // Теперь это безопасно
}
```

**2. Инициализация памяти (Функция `new`)**
Если тебе нужен указатель, и ты хочешь сам выделить под него память с нуля, можно использовать встроенную функцию `new`. Она выделяет кусочек памяти, кладет туда нулевое значение типа (например, `0` для `int`) и возвращает готовый, безопасный указатель.
```go
ptr := new(int) // Выделили память. ptr больше не nil!
*ptr = 10       // Безопасно пишем данные
```
