# Теория: Стек, Куча и Escape Analysis

Вся оперативная память, которую использует твоя программа на Go, грубо делится на две зоны: **Стек (Stack)** и **Куча (Heap)**. Разница между ними — это основа оптимизации производительности в Go.

## 1. Стек (Stack)
Стек — это сверхбыстрая память, которая выдается каждой горутине (потоку) индивидуально.
Когда вызывается функция, для нее на стеке создается "кадр" (фрейм). Все локальные переменные, созданные внутри функции, ложатся в этот кадр. 
**Главная фишка:** Как только функция завершает работу (делает `return`), её кадр мгновенно уничтожается, и вся память очищается автоматически без затрат процессора.

## 2. Куча (Heap)
Куча — это общая свалка памяти для всей программы. 
Выделение памяти в куче — долгий процесс. Но хуже того — память в куче нужно очищать. Этим занимается **Garbage Collector (Сборщик Мусора)**. Он периодически сканирует кучу, ищет переменные, которые больше никому не нужны, и удаляет их. Этот процесс отнимает ресурсы CPU и может вызывать микро-зависания программы (STW - Stop The World).

> **Золотое правило производительности Go:** Старайся держать переменные на Стеке. Чем меньше мусора летит в Кучу, тем реже просыпается Garbage Collector, и тем быстрее работает приложение.

## 3. Escape Analysis (Анализ "утечек" памяти)
В языках вроде C++ программист сам решает, куда положить переменную. В Go это решает компилятор. Этот процесс называется **Escape Analysis**.

Компилятор смотрит на твой код и задает один вопрос: *"Понадобится ли эта переменная кому-то после того, как функция, которая её создала, завершит работу?"*
- Если **НЕТ** — переменная остается на сверхбыстром Стеке.
- Если **ДА** — переменная "убегает" (escapes) в Кучу.

**Классический пример побега в Кучу:**
Если ты создал переменную внутри функции и вернул из функции **указатель** на нее, компилятор понимает: функция завершится, её Стек уничтожится, но кто-то снаружи всё еще держит указатель на эту переменную! Если оставить её на Стеке, указатель будет смотреть в мертвую зону (Dangling pointer).
Поэтому компилятор берет эту переменную и эвакуирует её в Кучу.

### Как подсмотреть за компилятором?
Go предоставляет встроенный инструмент для просмотра решений компилятора:
```bash
go build -gcflags="-m" .
```
Этот флаг (`-m`) заставит компилятор вывести на экран весь процесс Escape Analysis. Ты увидишь заветные слова `escapes to heap` (убегает в кучу) или `does not escape` (остается на стеке).
